# 进程、线程、协程：到底有什么区别？

## 一句话结论

**进程是操作系统分配资源（内存、文件、CPU）的最小单位，线程是 CPU 调度的最小单位，协程是用户态由程序自己调度、不依赖内核切换的轻量级执行流**。进程之间互相隔离、开销最大；线程共享进程内存、靠内核切换、开销中等；协程完全在用户态切换、开销最小，但通常跑在单个线程之上。

## 1. 从一个并发下载的例子说起

假设要写一个程序，同时下载 10 个文件。最朴素的做法是一个一个来：

```text
下载文件 1 → 等它完成 → 下载文件 2 → 等它完成 → ……
```

这样做的问题是：下载文件时大部分时间其实在「等网络返回」，CPU 一直闲着。于是人们想：「等待的时候能不能先去做别的事？」这就引出了三套不同的答案：

```text
用进程：开 10 个进程，每个下载一个文件
用线程：开 10 个线程，每个下载一个文件
用协程：写 10 个协程，遇到等待就主动让出，换下一个执行
```

同样是「同时下载」，三者的开销、隔离性和实现方式差别巨大。下面依次看。

## 2. 进程：操作系统的「资源容器」

### 2.1 进程是什么

进程是操作系统**分配资源的最小单位**。每一个正在运行的程序实例，就是一个进程。操作系统会为它单独划分：

```text
进程 = 独立的内存地址空间 + 打开的文件句柄 + 环境变量 + 运行时状态
```

关键点是「独立」。一个进程崩溃，通常不影响其他进程；一个进程越界访问内存，会被操作系统拦下来，不会破坏别人的内存。这就是**隔离性**。

### 2.2 进程间的通信

因为隔离，进程之间不能直接读写对方的变量，只能通过操作系统提供的机制传递数据：

```text
管道（Pipe）
共享内存（Shared Memory）
消息队列（Message Queue）
Socket / 网络
```

进程切换本身也不便宜：切换时要保存当前进程的全部上下文，还要切换页表、刷新 TLB，这个开销比线程切换大得多。

```text
进程开销大的原因：
  ① 创建进程要复制/分配独立地址空间
  ② 切换进程要切换页表，TLB 失效
  ③ 进程间数据传递要走内核
```

## 3. 线程：进程内部的「轻量执行流」

### 3.1 线程是什么

线程是 **CPU 调度的最小单位**。一个进程至少有一个线程，多个线程共享同一个进程的地址空间和资源，但各自拥有独立的执行栈和寄存器状态。

```text
┌─────────────────────────── 进程 ───────────────────────────┐
│  共享：内存空间 / 文件句柄 / 全局变量                          │
│  ┌────────┐   ┌────────┐   ┌────────┐                      │
│  │ 线程 A  │   │ 线程 B  │   │ 线程 C  │  每个线程有独立栈      │
│  └────────┘   └────────┘   └────────┘                      │
└────────────────────────────────────────────────────────────┘
```

线程因为共享内存，通信很方便——直接读写同一个变量就行，但这也带来了并发编程最经典的难题：**竞态条件**。

```python
import threading

counter = 0

def worker():
    global counter
    for _ in range(1_000_000):
        counter += 1

threads = [threading.Thread(target=worker) for _ in range(4)]
for t in threads:
    t.start()
for t in threads:
    t.join()

print(counter)  # 期望 4000000，实际往往小于它
```

`counter += 1` 在 CPU 里是「读 → 加 → 写」三步，两个线程可能同时读到同一个值，各自加 1 再写回，于是两次累加只生效了一次。修复办法是加锁，让这一步变成原子操作：

```python
import threading

counter = 0
lock = threading.Lock()

def worker():
    global counter
    for _ in range(1_000_000):
        with lock:
            counter += 1
```

```text
加锁的代价：同一时刻只有一个线程能进入临界区，其他线程要等待
这就是「并发」和「并行」的差别：
  并发：多个任务交替推进（宏观上都在进行）
  并行：多个任务在同一时刻真正同时运行（需要多核）
```

### 3.2 线程的切换靠内核

线程的调度由操作系统内核完成，切换时同样要进内核态，保存/恢复线程的上下文。相比进程切换少了页表切换，但仍有不可忽略的开销，线程多了之后「切换」本身会消耗不少 CPU。

## 4. 协程：用户态自己调度的「执行流」

### 4.1 协程是什么

协程是一种**在用户态由程序自己控制切换**的轻量级执行流。它不依赖操作系统调度，也没有内核参与，切换开销比线程小一个数量级，因此可以轻松创建成千上万个。

协程的关键特性是**主动让出（yield）**：遇到 I/O 等待时，协程主动挂起自己，把 CPU 让给其他协程，等数据就绪了再回来继续。

```text
线程：内核决定何时切换，谁也不知道什么时候被打断
协程：代码自己决定何时让出，切换点可控
```

Python 里用 `asyncio` 写协程非常自然：

```python
import asyncio


async def download(file_name: str) -> None:
    print(f"开始下载 {file_name}")
    await asyncio.sleep(1)  # 模拟网络等待
    print(f"下载完成 {file_name}")


async def main() -> None:
    await asyncio.gather(
        download("文件1"),
        download("文件2"),
        download("文件3"),
    )


asyncio.run(main())
```

输出是三个「开始下载」几乎同时出现，1 秒后三个「下载完成」几乎同时出现——因为 `await` 让协程在等待期间把执行权交还给了事件循环。

```text
事件循环（Event Loop）的工作方式：
  ① 有一个就绪队列，记录待运行的协程
  ② 取出一个执行，遇到 await 就挂起它
  ③ 去执行下一个，直到所有协程都阻塞
  ④ I/O 就绪后，把挂起的协程放回就绪队列
```

### 4.2 协程真能「并行」吗

要看场景：

```text
CPU 密集任务：协程并不能加速，因为它本质还是串行执行
I/O 密集任务：协程非常合适，等待时切换走，充分利用 CPU
```

所以协程的收益主要来自「把等待时间让出去」，而不是「让多个任务真的同时跑」。

## 5. 一张表分清三者

| 对比项 | 进程 | 线程 | 协程 |
| --- | --- | --- | --- |
| 分配的最小单位 | 资源（内存/文件/CPU） | CPU 调度 | ——（由线程承载） |
| 调度者 | 操作系统 | 操作系统内核 | 程序 / 运行时 |
| 切换成本 | 最大（含页表切换） | 中等（内核态切换） | 最小（用户态切换） |
| 地址空间 | 相互隔离 | 共享进程内存 | 共享线程内存 |
| 通信方式 | IPC（管道/共享内存/网络） | 直接读写共享变量 | 直接读写共享变量 |
| 创建数量级 | 几十～几百 | 几千 | 几十万 |
| 并发模型 | 多进程 | 多线程 | 单线程 + 事件循环 |
| 崩溃影响 | 一般不影响其他进程 | 可能拖垮整个进程 | 只影响所在线程 |

## 6. 分别适合什么场景

```text
进程：
  - 需要强隔离的场景（浏览器标签页、容器）
  - 需要独立崩溃互不影响的场景
  - 需要利用多核并共享大量状态较少的场景

线程：
  - 需要共享内存、又要利用多核并行计算的场景
  - CPU 密集且任务之间需要频繁交换数据

协程：
  - I/O 密集场景（网络请求、数据库访问、爬虫、网关）
  - 需要海量并发连接但不想开大量线程的场景
  - 业务代码希望写起来像同步、跑起来是异步
```

日常开发里最常见的组合是：**进程做部署单元，线程池做并行执行，协程做高并发 I/O**。

## 7. 常见误区

### 7.1 协程能完全替代线程吗？

不能。协程运行在单个线程之上，无法真正利用多核；CPU 密集任务仍需要多进程/多线程。两者是互补关系，不是替代关系。

### 7.2 开线程越多越好吗？

不是。线程切换有内核开销，线程数超过 CPU 核心数后，大量时间花在调度而非执行上，反而变慢。用线程池限制数量是常见做法。

### 7.3 协程是 Python 独有的吗？

不是。Go 的 goroutine、JavaScript 的 async/await、Rust 的 async、Kotlin 的 suspend 本质都是协程思想的不同实现。Go 里的 goroutine 还能自动跨越多个线程，由运行时调度。

### 7.4 多进程比多线程一定更安全吗？

安全性更高，但代价是通信复杂、内存开销大。而且「更安全」的前提是正确使用 IPC，否则同样会有各种并发问题。

### 7.5 协程里还会有竞态条件吗？

会。协程共享线程内存，虽然是协作式切换，但 `await` 打断点的存在意味着同一变量可能在切换期间被其他协程修改，共享状态时同样需要加锁或原子操作。

## 8. 总结

```text
进程：资源隔离的容器，成本最高，用来「互相不干扰」
线程：内核调度的执行流，共享内存，用来「并行干活」
协程：用户态调度，切换最便宜，用来「高效等待 I/O」
```

选择的关键在于想清楚问题的本质：是需要隔离，还是需要并行，还是只是想更高效地等待。搞清这三者的区别，是理解操作系统、并发编程和高性能服务设计的共同基础。
