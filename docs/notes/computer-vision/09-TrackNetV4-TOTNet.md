# TrackNetV4与TOTNet

---

## 1. 算法定位

这两个模型都属于**面向高速体育小目标的时空热图追踪**范畴，与第06、07章介绍的通用追踪算法不同，它们是专门为高速球类运动（网球、羽毛球、乒乓球、足球等）设计的专用模型。

```
高速小目标追踪的独特挑战:

挑战                  对常规方法的影响
─────────────────  ────────────────────────────
面积极小(~10-30px)   检测框置信度低，外观特征几乎无信息
高速运动(帧间百px)    帧间IoU可能为0，传统匹配失效
运动模糊             检测器频繁漏检，框位置不确定
频繁遮挡 (球员/球拍)  轨迹断裂，需要时序推理恢复
弱外观信息 (纯色球)   ReID方法不适用，只能依赖位置和运动
```

## 2. TrackNetV4

### 2.1 算法解决什么问题

TrackNetV4 面向高速体育小目标的追踪问题，直接输入连续多帧图像，输出目标在当前帧的位置热图。与前代版本（v1/v2/v3）相比，v4 的核心改进是**显式引入了可学习的运动注意力机制**，让模型优先关注帧间运动发生的区域。

### 2.2 核心架构

```
输入: 连续帧序列 (通常 3-5 帧)
     ↓
┌────────── 帧特征提取 ──────────────────┐
│  轻量 CNN Backbone (EfficientNet/MobileNet) │
│  逐帧提取特征图 F₁, F₂, ..., Fₙ            │
└──────────────────┬────────────────────┘
                   ↓
┌────────── 运动注意力模块 ──────────────┐
│                                          │
│  帧间差分: Diff = |Fₜ - Fₜ₋₁|            │
│     ↓                                    │
│  运动注意力: M = Conv(Diff) → 可学习权重  │
│     ↓                                    │
│  特征加权: F'_t = F_t ⊙ M               │
│   (增强运动区域，抑制静止背景)            │
└──────────────────┬────────────────────┘
                   ↓
┌────────── 时序特征聚合 ────────────────┐
│  3D Conv 或 ConvLSTM                      │
│  跨帧融合空间+时间信息                   │
└──────────────────┬────────────────────┘
                   ↓
┌────────── 解码 → 位置热图 ──────────────┐
│  Upsample + Conv → 单通道热图 (H × W)   │
│  热图峰值 → 球的 (x, y) 坐标            │
└───────────────────────────────────────┘
```

### 2.3 核心设计：运动引导注意力

这是 TrackNetV4 最核心的设计贡献，建立在以下先验知识上：

- 球体目标在宏观上一定处于运动状态（即使是短暂静止，相比帧率也是运动的）
- 帧间差分强度反映了运动在不同区域的剧烈程度
- 应该优先在运动发生的区域搜索目标，而不是整个画面均匀搜索

```
运动注意力效果:

原始帧:
┌──────────────────────────────┐
│  草地   球员    草地  球      │
│  静止   运动    静止  运动    │
└──────────────────────────────┘

帧差图:
┌──────────────────────────────┐
│  亮度0  亮区    亮度0  亮区  │
│          (球员)         (球) │
└──────────────────────────────┘

注意力权重:
┌──────────────────────────────┐
│  权重0  权重高  权重0  权重高│
└──────────────────────────────┘

加权后: 模型注意力集中在球员和球的区域
```

在羽毛球场、网球场等背景相对干净的场景中，运动注意力的效果非常好——因为背景中只有极少数干扰运动源（对手球员、裁判）。但在更复杂的背景（如足球广播画面中的观众席、广告牌变化、字幕滚动）中，需要配合其他空间先验来过滤虚假运动区域。

### 2.4 训练与推理

**训练**：

```
输入: N 帧连续帧 + 目标帧的真值位置 (x, y)
生成高斯热图: GT_heatmap = G((x,y), σ²)  ← σ 通常 2-4 px
Loss: MSE(预测热图, GT热图)
数据增强:
  - 随机裁剪
  - 亮度/对比度变化
  - 运动模糊模拟 (高速球的模糊外观)
  - 随机切帧 (模拟不同帧率)
```

热图方式的训练很自然——以真值坐标为中心生成高斯分布的模糊热图，MSE 损失让模型学会在真值位置产生最强的热图响应。σ 的选择影响定位精度：σ 太小 → 定位精确但训练困难（正样本区域太小），σ 太大 → 训练容易但定位模糊。

**推理**：

```
推理流程 (滑动窗口):
  FOR 每一帧作为目标帧 t:
      输入: [frame_{t-k}, ..., frame_t, ..., frame_{t+k}]
      前向传播 → 输出热图
      解码:
        方法1: argmax → 热图峰值坐标 (像素级，最简)
        方法2: soft-argmax → 亚像素坐标 (更精细)
        方法3: 多峰检测 → 如果出现多个峰，用运动连续性选择最近的
      输出: (x, y) 预测坐标
```

### 2.5 优缺点

| 优点 | 缺点 |
|------|------|
| 端到端训练，无需检测/追踪分离设计 | 训练数据需求量大（逐帧精确标注） |
| 对小目标敏感（热图优于框检测） | 时序窗口短（3-5帧），无法处理长遮挡 |
| 运动注意力有效减少背景干扰 | 热图多峰需要额外后处理 |
| 利用时序信息减少单帧运动模糊影响 | 镜头切换时窗口内容突变 → 预测不稳定 |
| 热图输出格式自然适合极小目标 | 背景复杂的场景（足球广播）效果降低 |

## 3. TOTNet

### 3.1 算法解决什么问题

TOTNet 专门面向体育球体追踪中的**遮挡问题**。高速球体被球员身体、球拍、球网等遮挡是频繁发生的，遮挡持续的时间可能从几帧到几十帧不等。TOTNet 的核心思想是：**如果模型学会了在可见时追踪球、在遮挡时推断球的位置，它就能在真实遮挡场景下表现得更好。**

TOTNet 被描述为面向遮挡的时序球体定位网络，使用 3D 卷积、可见性加权损失和遮挡增强。

### 3.2 核心架构

```
输入: 较长时序窗口 (7-16 帧)
     ↓
┌────────── 3D CNN 特征提取 ─────────────┐
│  3D 卷积核: 同时处理空间和时间           │
│  多尺度时空特征金字塔                    │
│  (与 TrackNetV4 的 2D+时序聚合不同，     │
│   3D CNN 一体化建模时间维度)             │
└──────────────────┬────────────────────┘
                   ↓
┌────────── 时序注意力 ──────────────────┐
│  Temporal Attention 加权不同帧的重要性   │
│  遮挡帧 → 低权重，可见帧 → 高权重        │
└──────────────────┬────────────────────┘
                   ↓
    ┌──────────────┴──────────────┐
    ↓                              ↓
┌─ 位置热图分支 ────────┐  ┌─ 可见性分支 ───────┐
│ Decoder → 热图 (H×W) │  │ Decoder → 分数[0,1]│
│ 每帧输出目标位置      │  │ 每帧输出可见性判断  │
└───────────────────────┘  └────────────────────┘
```

### 3.3 核心设计：以遮挡为中心

**① 更长时序窗口（7-16 帧）**

对比 TrackNetV4 的 3-5 帧窗口，TOTNet 的更长窗口提供了更丰富的时序上下文：

```
短窗口 (3帧): [可见, 遮挡, 遮挡] → 信息不足
长窗口 (7帧): [可见, 可见, 遮挡, 遮挡, 遮挡, 可见, 可见]
               ↑─ 利用遮挡前的轨迹推断 ─↑
```

**② 显式可见性预测**

TOTNet 的输出不仅仅是位置热图，还包括一帧的可见性分数。这提供了两重价值：
- 让模型知道自己"是否看到了球"，而不是被强迫输出一个猜测位置
- 可见性分数可以被下游系统（追踪器、事件检测器）利用来调整对位置预测的信任程度

**③ 遮挡增强训练**

在训练时主动合成遮挡样本：
```
原始训练帧:
  帧1: 球在位置A (可见)
  帧2: 球在位置B (可见)
  帧3: 球在位置C (可见)

遮挡增强:
  帧1: 球在位置A (可见)
  帧2: 球在位置B，将球区域替换为背景纹理 (合成遮挡)
  帧3: 球在位置C (可见)

同时修改可见性标签:
  帧2 的 visibility_gt = 0
```

通过大量暴露在模拟遮挡场景中，模型学会了在可见帧中追踪球、在遮挡帧中利用时序上下文推断球的位置。

**④ 可见性加权损失**

```
L_position = Σₜ visibility_gt[t] × MSE(heatmap[t], gt_heatmap[t])
L_visibility = Σₜ BCE(vis_pred[t], vis_gt[t])
L_total = L_position + λ × L_visibility
```

关键细节：**可见帧的定位错误受惩罚，不可见帧的定位错误被完全忽略。**这避免了模型在球完全被遮挡时被迫"猜"一个位置。

### 3.4 优缺点

| 优点 | 缺点 |
|------|------|
| 显式处理遮挡问题 | 3D CNN 计算量大 |
| 可见性预测提供可解释输出 | 长时序窗口训练需要大量显存 |
| 利用前后帧的时间推断恢复遮挡位置 | 可见性阈值需要调参 |
| 遮挡增强 → 模型泛化性更好 | 训练数据与真实场景的域差距可能大 |
| 可见性加权 → 训练更聚焦有效区域 | 热图多峰问题仍存在 |

### 3.5 与 TrackNetV4 的对比

| 维度 | TrackNetV4 | TOTNet |
|------|-----------|--------|
| Backbone | 2D CNN 逐帧提取 | 3D CNN 统一时空 |
| 时序窗口 | 3-5 帧 | 7-16 帧 |
| 时序处理 | 运动注意力 + ConvLSTM/3D Conv | 3D Conv + Temporal Attention |
| 内存开销 | 较小 | 较大 |
| 可见性 | 不显式输出 | 显式可见性预测 |
| 遮挡设计 | 隐式（靠时序窗口） | 显式（可见性 + 遮挡增强） |
| 训练数据 | 较少即可 | 需要可见性标注 |

## 4. 为什么用热图而非边界框？

这关系到高速小目标追踪的根本设计选择。

```
热图 vs 边界框 (针对极小目标):

边界框检测:
  锚框 (Anchor):         热图检测:
  ┌────────────────┐         ┌────────────────┐
  │  ████ (框)     │         │  ·  ·  ·       │
  │  ████ 球太小   │         │  ·  ■  ·       │ ← 峰值
  │  ████          │         │  ·  ·  ·       │
  └────────────────┘         └────────────────┘
  问题: 框内大量背景          优势: 只关注目标中心的概率
        框尺寸变化剧烈              表示，不受尺寸影响
```

- 热图天然不受目标尺寸影响——无论是 20px 的球还是 10px 的球，热图只需要在目标中心产生一个峰值
- 热图不需要处理框的长宽比（篮球场上的球是正圆的，不需要模型学习 w/h）
- 在极端尺寸下（< 10px），热图的峰值定位比框回归更鲁棒
- 训练目标（高斯热图）和网络输出具有一致的结构，优化更稳定

## 5. 在足球追踪中的适用性

### 5.1 优势场景
- 中近景镜头：球面积 > 15px，运动信息丰富
- 较短遮挡（< 0.5 秒，即 < 15 帧）：时序窗口可以覆盖
- 背景相对干净（特写或慢动作回放）

### 5.2 局限性
- 足球广播背景比网球/羽毛球复杂得多（观众席、广告牌、字幕滚动）
  → 运动注意力可能被大量背景运动干扰
- 纯色足球外观信息弱 → 当多个白色运动目标同时出现时容易混淆
- 镜头频繁切换（足球广播比网球多得多）
  → 时序窗口经常跨越镜头边界，窗口内容突变
- 原始模型训练数据以网球/羽毛球为主 → 域差距大
- 足球场尺寸大，球在图像中可小到 5px 以下 → 超出热图定位能力

### 5.3 推荐的角色

不作为独立追踪器，而作为**时序验证模块**配合检测器使用：

```
RT-DETR 检测候选
      ↓
TrackNet/TOTNet 热图验证
      ↓
候选位置热图响应高 → 候选可信
候选位置热图响应低 → 候选可疑
热图高响应但检测低分 → 候选被检测遗漏，应被添加
检测高分但热图低响应 → 可能是假球，应被降权
```

这种配合方式发挥了两个方法的互补优势：
- RT-DETR：基于单帧的空间特征（哪个区域像球）
- TrackNet/TOTNet：基于多帧的时序特征（哪个区域是连续的球轨迹）

## 6. 工程实现难点

### 6.1 热图多峰处理

这是时序热图方法在实际部署中最棘手的工程问题：

```
热图可能出现多峰的情况:
  假球1: 白色球鞋在运动
  真球: 足球在飞行
  假球2: 白色广告中的圆形物体

  热图:  ●      ■      ●
        (假球1) (真球) (假球2)
```

处理方法：
- 多峰检测：使用峰值检测算法（非极大值抑制）找到所有候选峰
- 运动连续性筛选项：与前一帧预测位置最近的峰优先
- 如果多个峰都与预测位置距离相近 → 增加不确定性 → 等待下一帧更多信息
- 极端情况下，让 Viterbi 在后续帧做全局判断来解决局部歧义

### 6.2 时序窗口与镜头切换

这是所有时序方法在足球场景的共同问题：

- 足球广播每分钟 10-20 次镜头切换
- 时序窗口经常跨越切换边界 → 窗口内容完全突变
- 切换帧附近的预测结果混乱
- 需要配合镜头切换检测模块

应对策略：
- 检测到镜头切换 → 丢弃包含切换帧的窗口输出
- 切换后重新构建窗口（需要积累至少 k 帧才能重新开始预测）
- 切换后的前 k 帧使用单帧检测器结果（TrackNet/TOTNet 不可用）

### 6.3 训练数据标注
- 逐帧精确标注小球位置：需要逐帧放大/逐帧点击，极其耗时
- 单人标注一场 45 分钟比赛 → 可能数天工作量
- 运动模糊帧的位置标注 → 本身就存在不确定性（模糊的球，中心在哪？）
- 遮挡帧的标注约定：
  - 标注球不可见（visibility=0） → 模型学会等待
  - 标注估计位置 → 模型可能过于自信

### 6.4 跨域泛化
- 不同体育项目：篮球 vs 足球 → 外观、运动模式、背景完全不同
- 不同比赛/联赛：拍摄风格差异（英超快切 vs 意甲长镜头）
- 不同场地：白天 vs 夜间、晴天 vs 雨天 → 光照条件剧变
- 缩放和分辨率：不同摄像机的近景/远景比例不同

### 6.5 TOTNet 3D CNN 的计算开销
- 3D 卷积是将 2D 核扩展为 3D 核，计算量翻倍
- 长时序窗口（16 帧）→ 3D 特征图体积巨大
- 显存峰值高 → 训练需要小 Batch → 梯度不稳定
- 推理时 3D 卷积的算子优化不如 2D 卷积成熟

### 6.6 光流作为替代/辅助

如第 4 章所述，光流可以作为运动信息的另一个来源：

```
场景: TrackNet/TOTNet 热图存在多峰歧义

光流辅助判断:
  检测候选框
      +
  局部光流方向 (RAFT / Farnebäck)
      ↓
  候选的运动方向 vs 光流的运动方向
  一致性 → 候选可信
  不一致 → 候选可疑
```

但光流不能替代 TrackNet/TOTNet：
- 光流容易跟随背景纹理（草地、白线）而非足球
- 快速运动超出光流搜索范围后失效
- 遮挡后光流信号丢失
