# Fine-tuning 中的 Packing：加与不加，主要区别是什么？

## 一句话结论

**Packing 把多条较短的训练样本装进同一个计算序列，减少 padding 浪费，通常能提高有效 Token 吞吐；但它是否改变训练效果，取决于样本间注意力是否隔离、位置与 loss 是否正确处理，以及每次参数更新实际包含多少训练数据。**

因此，“加 packing”不等于“模型一定更强”，也不一定等于“只是无损提速”。先看实现到底做了什么，再比较效率和效果。

本文以 **decoder-only 大模型的监督微调（SFT）** 为例；全参数微调与 LoRA 都可能使用 packing，它与“训练哪些参数”是两个独立维度。

## 1. 不加 Packing，GPU 在浪费什么？

假设有三条已套用聊天模板、包含结束标记的样本：

```text
A：6 个 Token
B：4 个 Token
C：5 个 Token
```

若每条都补到固定长度 16，再组成 batch：

```text
不加 packing，张量形状为 [3, 16]：
[ A A A A A A · · · · · · · · · · ]
[ B B B B · · · · · · · · · · · · ]
[ C C C C C · · · · · · · · · · · ]

加 packing，装成一个长度为 16 的 pack：
[ A A A A A A B B B B C C C C C · ]

· 表示 padding；字母表示属于相应样本的 Token。
```

两种方式都保留 15 个真实 Token，但分配的 Token 槽位从 48 个变成 16 个：

$$
\text{槽位利用率}_{\text{unpacked}}=\frac{15}{48}=31.25\%,
\qquad
\text{槽位利用率}_{\text{packed}}=\frac{15}{16}=93.75\%
$$

**核心收益是：让原本装 padding 的位置，装上真正的训练数据。** Padding 即使不参与 loss，在普通稠密计算路径里也可能占用激活、FFN 计算和部分注意力计算资源。

不过，不加 packing **不代表一定补到最大上下文长度**。若使用动态 padding，这个 batch 只补到最长样本的 6 个 Token，总槽位是 $3\times6=18$，利用率已达 $15/18\approx83.3\%$。再配合按长度分桶，浪费还可能降低。

所以，上面的槽位数减少到三分之一，**不能直接解释为训练必然加速 3 倍**。实际收益取决于原有 padding 比例、算子、数据准备和硬件利用率。

## 2. 最关键的区别：拼在一起以后，样本能互相看见吗？

### 2.1 直接拼接：后面的样本能看到前面的样本

一种简单做法是把数据拼为：

```text
[样本 A + EOS][样本 B + EOS][样本 C + EOS]
```

若仍使用普通的因果注意力，B 中的 Token 可以关注 A，C 可以关注 A 和 B。因果 mask 只保证“不能看未来”，并不保证“不能看其他样本”。

**EOS 是结束标记，不是一道自动生效的注意力隔离墙。** 模型可能学会利用结束标记，但这不等于框架已经阻止跨样本注意力。

对本来应独立的问答任务，这会改变条件分布：原来是“给定 B 自己的 prompt 预测回答”，现在可能变成“给定 A 的全部内容和 B 的 prompt 预测回答”。这种差异不必然导致效果变差，但已不再是纯粹的数据排布优化。

### 2.2 边界隔离的 Packing：物理拼接，逻辑独立

若目标是尽量保持独立样本的语义，则需要**块对角的因果注意力**。设 $s(i)$ 表示第 $i$ 个 Token 所属的样本，允许关注的位置满足：

$$
\operatorname{allow}(i,j)
=\mathbf{1}[s(i)=s(j)]\,\mathbf{1}[j\le i]
$$

也就是同时满足“同一条样本”和“不看未来”：

```text
              Key 所属样本
                A   B   C
Query 属于 A   [△   ×   ×]
Query 属于 B   [×   △   ×]
Query 属于 C   [×   ×   △]

△：样本内部的因果注意力
×：禁止跨样本关注
```

实际实现不一定显式构造大 mask。支持变长序列的注意力算子，可以通过各样本长度、累计长度（如 `cu_seqlens`）等元数据识别边界，在紧凑布局上分别计算注意力。

**普通的二维 0/1 padding mask，通常不足以表达这种样本边界；仅重置 `position_ids` 也不自动意味着注意力已经隔离。** 必须确认所用模型与注意力后端真正消费了边界信息。

## 3. 要保持训练语义，还要处理哪三件事？

### 3.1 位置编码：每条样本应该处于什么位置？

独立训练时，A、B、C 通常各自从位置 0 开始。打包以后，如果位置直接连续累加，B、C 就被放到了更靠后的上下文位置。

若希望与独立训练对齐，通常应在每条样本边界重置位置，或由变长算子提供等价的位置语义。具体做法取决于模型的位置编码和框架实现，不能假设所有模型都一样。

但重置位置与隔离注意力解决的是两个问题：**前者决定“我在哪里”，后者决定“我能看谁”。** 两者不能互相替代。

### 3.2 Loss Mask：哪些 Token 应该成为学习目标？

SFT 经常只对 assistant 的回答计算 loss，prompt 仍参与前向计算，但不作为监督目标。Packing 后必须保留每条样本原来的监督范围：

```text
样本 A：[user prompt][assistant answer][EOS]
loss：       忽略              计算       通常计算

样本 B：[user prompt][assistant answer][EOS]
loss：       忽略              计算       通常计算
```

尤其要注意自回归训练的 **label shift**：模型在当前位置预测下一个 Token。不能因为 A 和 B 在内存中相邻，就额外要求“A 的最后一个位置预测 B 的第一个 Token”。

如果采用常见的“传入未移位 labels、模型内部 shift”约定，应屏蔽后续样本首 Token 对应的目标；其他框架可能通过预先对齐 labels、loss mask 或边界逻辑完成同样的处理。**应按实际 shift 方式检查，不能机械地屏蔽某一个固定张量位置。**

同时，要保留回答结束标记的正常监督，避免误把“学习何时停止”一起删掉。Attention mask 控制可见上下文，loss mask 控制监督目标，这两者也不能混为一谈。

### 3.3 Loss 归一化：按 Token 平均，还是按样本平均？

设 $m_{i,t}$ 表示样本 $i$ 的第 $t$ 个目标 Token 是否参与监督。常见的 Token 平均 loss 为：

$$
\mathcal L_{\text{token}}
=\frac{\sum_i\sum_t m_{i,t}\ell_{i,t}}
       {\sum_i\sum_t m_{i,t}}
$$

它与“先对每条样本求平均，再对样本求平均”不同：前者让监督 Token 更多的样本占更大权重。**不应把每个 pack 当成一个等权样本随意平均**，否则装箱方式本身就可能改变训练权重。

如果希望 packing 前后对齐，就要保持相同的加权规则；梯度累积和多卡训练时，也要检查最终是否按预期的有效监督 Token 数归一化。

## 4. 加与不加的主要区别，一张表看清

| 维度 | 不加 Packing | 加 Packing |
| --- | --- | --- |
| 数据布局 | 常见为一条样本占一行，配合 padding | 一行或紧凑缓冲区容纳多条样本 |
| Padding 浪费 | 长度差异大时可能较多；动态 padding、分桶能改善 | 通常更少，但仍可能有尾部空位和对齐 padding |
| 样本间注意力 | 不同 batch 行天然隔离 | 取决于实现，直接拼接可能允许跨样本关注 |
| 每步原始样本数 | 较容易按 batch 行数估计 | 一个 pack 可含多条，不能直接按行数理解 |
| Loss 与位置处理 | 边界较直观 | 需要保留边界、位置语义和原有监督 mask |
| 速度与显存 | 基线更易排查 | 通常提升有效吞吐，但不保证更快或峰值显存更低 |
| 模型效果 | 取决于数据和训练设置 | 不是天然更好；语义与预算对齐时应接近，具体需评估 |

### 为什么加了 Packing，注意力反而可能更贵？

只把长度为 $l_1,l_2,\ldots$ 的样本拼接，再执行覆盖整个 pack 的稠密注意力，其注意力计算规模可能接近：

$$
\left(\sum_i l_i\right)^2
$$

而真正利用边界的变长注意力，可以按各样本分别计算，规模更接近：

$$
\sum_i l_i^2
$$

这里省略了隐藏维度等因素，只比较序列长度相关项。**显式写上块对角 mask，也不代表底层算子一定跳过被屏蔽的计算。** 因此，要同时看 packing 策略和注意力后端，不能只看开关。

在相同物理 batch 形状下，packing 往往是“同样的空间装入更多有效数据”，而不是“自动减少所有显存”。如果同时增大 pack 长度、改变 batch 或算子，峰值显存还可能上升。

## 5. 为什么相同 Batch Size、相同 Steps，不是公平比较？

假设不加 packing 时，每步处理 8 条原始样本；加 packing 后，仍设置 8 行，但每个 pack 平均容纳 4 条样本，那么每步实际处理约 32 条原始样本。

此时即使学习率、梯度累积步数和训练 steps 完全相同，**每次更新见到的数据量，以及总训练数据量，都已经变了**。不能把效果变化全部归因于 packing。

建议区分三种计数：

1. **物理槽位数：** 决定张量规模，但包含 padding。
2. **非 padding Token 数：** 反映实际输入数据量，包含 prompt。
3. **有效监督 Token 数：** 真正参与 loss 的目标数量；answer-only SFT 中通常更少。

做效果对比时，应尽量对齐原始数据覆盖、截断规则、每次更新的有效数据量、loss 加权，以及学习率和 warmup 对应的数据进度。只固定最大 steps，很容易让两边训练的不是同一份预算。

即使这些都对齐，也不应要求参数逐位一致：装箱和长度分桶可能改变样本顺序，算子与随机数路径也可能不同。合理目标是**相近的训练目标和可比较的任务效果**。

## 实践建议

如果要在实际微调中决定是否开启 packing，可以按以下顺序做：

1. **先统计长度与 padding 比例。** 使用套好聊天模板后的 Token 长度；短样本多、长短差异大时通常更值得尝试。若样本已接近目标长度，或已有高效的去 padding 路径，收益可能有限。
2. **确认 packing 的语义。** 查看当前框架版本、模型与注意力后端是否支持样本隔离；不要只凭 `packing=True` 就推断它是无跨样本注意力的实现。
3. **检查一小批打包结果。** 对照 `input_ids`、边界信息、`position_ids` 和 labels，确认聊天模板、EOS、回答监督范围与跨样本 shift 都正确；特别检查截断、拆分及尾包丢弃规则。
4. **验证隔离是否真的生效。** 在 eval 模式关闭 dropout，把同一个 B 单独前向和放在 A 后面打包前向，比较 B 的有效位置 logits 或 loss。对于声称语义等价的实现，差异应处于合理数值误差范围；更换无关的 A 不应系统性改变 B 的结果。
5. **对齐预算再跑对照。** 记录每次更新的非 padding Token、监督 Token 和原始样本数，必要时调整 batch 与梯度累积，而不是直接复制 steps。
6. **同时测性能和效果。** 看有效输入 Token/s、监督 Token/s、完整训练耗时、峰值显存及独立验证集表现；不要仅用“包含 padding 的 Token/s”判断收益。

还要避免一个常见误解：**把 8 条独立的 512-Token 样本装成 4096-Token 的 pack，不等于模型学习了跨 4096 Token 的长程依赖。** 若样本注意力相互隔离，每条样本能使用的上下文仍只有自己的那部分。Packing 优化装箱，不会凭空生成长上下文训练数据。

最终可以这样记：**不加 packing，是“每条样本单独占位置”；加 packing，是“多条样本共用计算容器”。效率取决于空位减少了多少、算子是否高效；效果是否变化，则取决于有没有保持样本边界、监督目标和训练预算。**
