# 目标追踪

目标追踪的任务是在连续帧中保持对象身份的一致性。与目标检测不同，追踪不仅要回答"目标在哪里"，还要回答"这是上一帧的哪个目标"。

---

## 1. 任务分类

### 1.1 SOT（单目标追踪）

给定第一帧的目标框，在后续帧中持续跟踪该单一目标。典型应用：无人机跟拍、视频稳定。

代表性方法：
- 相关滤波类：KCF、ECO
- Siamese 网络类：SiamFC、SiamRPN、SiamMask

### 1.2 MOT（多目标追踪）

同时跟踪视频中所有感兴趣的目标，自动处理目标的出现、消失和交互。典型应用：行人追踪、体育分析、自动驾驶。

MOT 可进一步分为：
- **Online（在线）**：逐帧处理，仅利用当前及过去帧的信息，适合实时场景
- **Offline（离线/Batch）**：利用整个视频片段的信息（含未来帧），精度更高但有时延

## 2. 追踪范式

### 2.1 TBD（Tracking-by-Detection）

当前 MOT 的主流范式，分两步独立执行：

```text
视频帧 → 目标检测 → 特征提取 → 数据关联 → 轨迹管理
```

| 步骤 | 说明 |
|------|------|
| 目标检测 | 逐帧运行检测器（如 YOLO、Faster R-CNN），得到当前帧的所有检测框 |
| 特征提取 | 为每个检测框提取外观特征（如 ReID 特征）和/或运动特征 |
| 数据关联 | 将当前帧的检测与已有轨迹进行匹配，常用匈牙利算法或贪心匹配 |
| 轨迹管理 | 创建新轨迹、关闭消失轨迹、处理遮挡时的暂态丢失 |

**优缺点**：检测器可独立升级，灵活性高；但整体性能受限于检测质量，且处理速度受检测器拖累。

### 2.2 Joint Detection-Tracking

检测和追踪在同一网络中联合完成，代表性方法：

- **FairMOT**：在单网络中同时输出检测 heatmap 和 ReID 特征，anchor-free 设计
- **ByteTrack**：利用低分检测框参与二次匹配，显著降低漏检
- **CenterTrack**：基于 CenterNet 的端到端追踪，预测相邻帧的目标偏移

**优缺点**：速度快，端到端优化潜力大；但灵活性较低，难以独立更换检测器。

### 2.3 跟踪式追踪（Tracking by Attention）

利用 Transformer 的交叉注意力机制在帧间传播目标特征：

- **CoTracker**：通过 Transformer 联合处理多帧、多点轨迹，不依赖显式检测
- **TrackFormer**：将追踪视为 Transformer 的时序检测任务，检测与追踪共用 query

## 3. 数据关联

数据关联是 MOT 的核心环节，解决"当前检测属于哪个已有轨迹"的分配问题。

### 3.1 代价矩阵

构建一个 $N \times M$ 的矩阵（$N$ 个已有轨迹，$M$ 个当前检测），每个元素表示轨迹 $i$ 与检测 $j$ 之间的匹配代价。代价通常由两部分加权组合：

- **运动代价**：基于卡尔曼滤波预测的位置与检测框的 IoU 或马氏距离
- **外观代价**：轨迹外观特征与检测外观特征之间的余弦距离

### 3.2 匹配算法

| 方法 | 策略 | 特点 |
|------|------|------|
| 匈牙利算法 | 全局最优二分图匹配 | 经典方法，复杂度 $O(N^3)$ |
| 贪心匹配 | 按代价从小到大依次匹配 | 速度快，适合大规模场景 |
| 级联匹配 | 优先匹配最近更新的轨迹 | 处理遮挡后恢复 |
| 二次匹配 | ByteTrack 方式，用高分框一次匹配，低分框二次匹配 | 减少漏检 |

### 3.3 生命周期管理

```
未匹配的检测 → 创建新轨迹（暂态，确认后转为正式）
未匹配的轨迹 → 保留（暂态）→ 超过阈值 → 消亡
匹配成功的轨迹 → 更新状态（卡尔曼滤波），标记为活跃
```

典型参数：
- `max_age`：轨迹在消失后最多保留的帧数（通常 30-60）
- `min_hits`：新轨迹需要连续匹配多少次才转为正式轨迹（通常 2-3）

## 4. 运动预测

### 4.1 卡尔曼滤波（Kalman Filter）

MOT 中最常用的运动模型，假设目标做匀速或匀加速运动：

- **预测**：根据上一帧状态预测当前帧位置
- **更新**：用当前帧的检测结果修正预测

卡尔曼滤波的优势在于计算量小、适合在线推理，但无法处理剧烈变速和方向突变。

### 4.2 运动模型对比

| 模型 | 适用场景 | 复杂度 |
|------|---------|--------|
| 匀速模型（Constant Velocity） | 常规行人/车辆追踪 | 低 |
| 加速度模型 | 体育场景中快速变向 | 中 |
| IMM（交互式多模型） | 多模式运动切换（如行走→奔跑） | 高 |
| 无迹卡尔曼滤波（UKF） | 强非线性运动 | 高 |

## 5. 常见指标

### 5.1 MOTA（Multiple Object Tracking Accuracy）

MOTA 是 MOT 最经典的综合性指标，反映追踪的总体准确度：

$$ \text{MOTA} = 1 - \frac{\text{FN} + \text{FP} + \text{IDSW}}{\text{GT}} $$

- **FN**：漏检数（False Negative）
- **FP**：误检数（False Positive）
- **IDSW**：身份切换数（ID Switch）
- **GT**：真实标注数

MOTA 可以小于 0（当错误比真实标注还多时），且不区分不同类型的错误。

### 5.2 IDF1（Identification F1）

IDF1 关注身份保持的质量，衡量预测轨迹与真实轨迹的匹配程度：

$$ \text{IDF1} = \frac{2 \cdot \text{IDTP}}{2 \cdot \text{IDTP} + \text{IDFP} + \text{IDFN}} $$

IDF1 更关注"身份一致性"，而 MOTA 更关注"检测质量"。两个指标需要结合使用。

### 5.3 HOTA（Higher Order Tracking Accuracy）

HOTA 将评估分解为三个维度：

$$ \text{HOTA} = \sqrt{\text{DetA} \cdot \text{AssA}} $$

- **DetA（Detection Accuracy）**：检测定位的质量
- **AssA（Association Accuracy）**：关联/身份保持的质量

HOTA 的设计目标是平衡检测与关联，避免 MOTA 偏向检测、IDF1 偏向关联的不足。

### 5.4 其他辅助指标

| 指标 | 含义 |
|------|------|
| MT（Mostly Tracked） | 轨迹被跟踪超过 80% 的比例 |
| ML（Mostly Lost） | 轨迹被跟踪低于 20% 的比例 |
| FP / FN | 误检 / 漏检总数 |
| Frag | 轨迹碎片化次数（同一轨迹被断开再重连的次数） |

## 6. 数据集与基准

| 数据集 | 场景 | 指标 | 特点 |
|--------|------|------|------|
| MOT17 / MOT20 | 行人 | MOTA, IDF1, HOTA | 经典行人 MOT 基准 |
| DanceTrack | 舞蹈 | HOTA, AssA | 强调外观相似下的关联能力 |
| SportsMOT | 体育 | HOTA | 快速运动、目标小 |
| KITTI | 自动驾驶 | MOTA | 行人 + 车辆 |
| TAO | 开放世界 | mMOTA | 长尾类别追踪 |
| SoccerNet-Tracking | 足球 | MOTA, HOTA | 体育专用追踪基准 |

## 7. 关键挑战

- **遮挡**：目标被其他物体遮挡时轨迹容易中断或发生 ID Switch
- **外观相似**：同类别目标之间外观区分度低（如足球运动员穿着统一队服）
- **快速运动**：帧间位移大，运动模型预测困难
- **尺度变化**：目标靠近/远离镜头时框大小剧烈变化
- **目标交互**：人与人、人与物之间的遮挡和碰撞增加关联歧义
- **边缘案例**：目标短暂出镜后重新出现、新目标入场与旧目标离场
