# LLM 训练之 DPO：直接从偏好对优化模型

## 一句话结论

**DPO（Direct Preference Optimization，直接偏好优化）用“同一问题下，回答 A 比回答 B 更好”的数据，直接微调语言模型：让好回答相对坏回答的对数概率差，比冻结参考模型中的差距更大。它不需要单独训练奖励模型，也不需要在标准离线训练循环中实时生成回答、估计优势再做 PPO 更新。**

它仍然需要可信的偏好数据，而且优化的是**相对偏好**，不是“所有 chosen 回答的绝对概率一定上升”。本文讨论原始的、基于 Sigmoid 损失的离线 DPO；后续的在线版本和其他偏好损失应另看具体配方。

## 1. SFT 已经教模型回答，为什么还需要 DPO？

假设在训练一个后端技术助手，用户问：

> 支付回调可能重复发送，怎样避免重复发货？

我们有两个候选回答：

| 字段 | 教学示例 |
| --- | --- |
| `prompt` | 支付回调可能重复发送，怎样避免重复发货？ |
| `chosen` | 验签并核对订单信息，以支付流水或业务事件标识做幂等；通过数据库唯一约束和事务记录处理结果，再可靠地触发发货。 |
| `rejected` | 使用内存布尔变量记录已经处理，重复回调直接忽略即可。 |

这里偏好 chosen，是因为 rejected 没有解决重启、多实例和并发下的重复处理。实际生产方案还要考虑事务边界与下游发货幂等，详见[幂等性笔记](/notes/backend/15-idempotency)。

**SFT 学“给定问题，模仿这个示范答案”；DPO 学“给定问题，这个答案比另一个更值得生成”。** 只拿 chosen 做 SFT 也能利用这份数据，但没有显式使用 rejected 提供的对照。

偏好对不要求“一个完美、一个完全错误”：两条都基本正确，也可以比较具体性、简洁性或指令遵循。关键是判断标准一致，且两条回答面对的是**相同的完整上下文**。偏好可以来自人工、AI 评审或规则，但 chosen 只表示按当前标准胜出，不是绝对正确的认证。

## 2. DPO 损失：四个对数概率，一次成对比较

记问题为 $x$，好回答为 $y_w$，差回答为 $y_l$：

- $\pi_\theta$：正在训练的语言模型，通常从 SFT 模型初始化。
- $\pi_{\mathrm{ref}}$：冻结的参考模型，通常取训练开始前的同一个 SFT 检查点。
- $\beta>0$：控制偏好尺度、并与理论中的 KL 正则强度对应的超参数。

先定义每条回答相对参考模型的对数概率变化：

$$
\Delta_w=\log\pi_\theta(y_w\mid x)-\log\pi_{\mathrm{ref}}(y_w\mid x)
$$

$$
\Delta_l=\log\pi_\theta(y_l\mid x)-\log\pi_{\mathrm{ref}}(y_l\mid x)
$$

一对样本的偏好 margin 与损失为：

$$
m=\beta(\Delta_w-\Delta_l),
\qquad
\ell_{\mathrm{DPO}}=-\log\sigma(m)
$$

整个数据集的目标就是对该损失取平均。$\sigma$ 是 Sigmoid；$m$ 越大，模型对“chosen 胜过 rejected”的预测概率 $\sigma(m)$ 越高，损失越小。

把括号展开，更容易看出参考模型的作用：

$$
\Delta_w-\Delta_l
=\underbrace{\log\frac{\pi_\theta(y_w\mid x)}{\pi_\theta(y_l\mid x)}}_{\text{当前模型中的好坏差距}}
-\underbrace{\log\frac{\pi_{\mathrm{ref}}(y_w\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}}_{\text{参考模型中的好坏差距}}
$$

**DPO 不是只要求当前模型把 chosen 排在前面，而是让这对回答的相对概率比，在参考模型的基础上进一步向 chosen 倾斜。** 参考模型提供的是锚点，不是给答案打分的独立奖励模型。

### 一个数值例子

以下使用完整回答的自然对数概率，固定参考模型的 chosen / rejected 分别为 $-20$、$-22$，取 $\beta=0.1$：

| 当前模型状态 | chosen Logprob | rejected Logprob | $\Delta_w-\Delta_l$ | $m$ | 损失，约 |
| --- | --- | --- | --- | --- | --- |
| 与参考模型相同 | -20 | -22 | 0 | 0 | 0.693 |
| 好回答提高，差回答降低 | -19 | -23 | 2 | 0.2 | 0.598 |
| 两个都降低，但差回答降得更多 | -22 | -25 | 1 | 0.1 | 0.644 |

初始化时，即使参考模型已经更偏向 chosen，DPO margin 仍为 0，因为它衡量的是**相对参考模型新增的偏好差距**。这里的 0.5 是偏好模型的预测值，不是“生成 chosen 的概率为 50%”。

第三行说明：**DPO loss 下降，不保证 chosen 的绝对概率上升。** 共享参数与整个回答空间的概率归一化，使成对排序改善和绝对似然改善成为不同的事情；所以不能只看训练 loss 判断生成质量。

## 3. 为什么可以跳过奖励模型和强化学习循环？

经典偏好型 RLHF 常先学习奖励函数 $r(x,y)$，再优化一个带 KL 惩罚的目标：

$$
\max_\pi\;
\mathbb E_x\left[
\mathbb E_{y\sim\pi(\cdot\mid x)}[r(x,y)]
-\beta D_{\mathrm{KL}}\!\left(
\pi(\cdot\mid x)\Vert\pi_{\mathrm{ref}}(\cdot\mid x)
\right)
\right]
$$

对于给定奖励，在适当的支持与归一化条件下，最优策略满足：

$$
\pi^*(y\mid x)
=\frac{\pi_{\mathrm{ref}}(y\mid x)\exp(r(x,y)/\beta)}{Z(x)}
$$

将它反过来写，得到：

$$
r(x,y)
=\beta\log\frac{\pi^*(y\mid x)}{\pi_{\mathrm{ref}}(y\mid x)}
+\beta\log Z(x)
$$

再假设偏好服从 Bradley–Terry 模型：

$$
P(y_w\succ y_l\mid x)=\sigma\bigl(r(x,y_w)-r(x,y_l)\bigr)
$$

由于两个回答面对同一个 $x$，相减时 $\beta\log Z(x)$ 消失。用可训练的 $\pi_\theta$ 参数化策略，代入后就得到上一节的 DPO 损失。

这就是“语言模型也是隐式奖励模型”的含义：可以定义
$\hat r_\theta(x,y)=\beta\log[\pi_\theta(y\mid x)/\pi_{\mathrm{ref}}(y\mid x)]$，直接拟合偏好，无需额外训练一个输出标量奖励的网络。

**这是一种有假设的重参数化，不代表有限偏好数据上的 DPO，必然等价于任意实际 PPO 训练结果。** 数据覆盖、偏好噪声、模型容量和优化误差，都会影响最终策略。

### $\beta$ 应该怎样理解？

在上面的 KL 正则目标中，固定奖励时，更大的 $\beta$ 会让理论最优策略更靠近参考模型。但在实际 DPO 损失中，$\beta$ 还会改变 Sigmoid 的尺度与梯度：

$$
\nabla_\theta\ell
=-\beta\sigma(-m)\left[
\nabla_\theta\log\pi_\theta(y_w\mid x)
-\nabla_\theta\log\pi_\theta(y_l\mid x)
\right]
$$

排序错误或差距不足的样本权重更大，已经大幅分开的样本权重更小。不能简单把 $\beta$ 当作学习率，也不能说“越大，每一步更新一定越小”。应结合学习率、训练轮数与验证集结果一起调节。

## 4. 一轮 DPO 训练实际做什么？

```text
准备 SFT 检查点与离线偏好对 (prompt, chosen, rejected)
    ↓
初始化可训练策略，冻结参考策略
    ↓
对两条回答分别进行 teacher-forcing 前向，得到回答 Token 的 Logprobs
    ↓
策略 Logprobs 保留梯度，参考 Logprobs 不保留梯度
    ↓
计算相对参考的偏好 margin，再计算 -logsigmoid(margin)
    ↓
反向传播，仅更新策略参数
```

Teacher forcing 表示把已有回答作为输入，计算其各个 Token 的条件概率，**不是在每步训练时重新生成回答**。候选生成和评审仍可能是离线数据准备的主要成本。

### 核心 PyTorch 实现

下面仅展示序列打分和损失；假设 decoder-only 模型、普通右侧 padding、未 packing，每行是已经套好模板的 `[prompt][answer][结束标记][padding]`：

```python
import torch
import torch.nn.functional as F

def completion_logps(logits, input_ids, completion_mask):
    # logits: [B, L, V]；mask 仅在回答及其结束标记处为 1
    # 位置 t 的 logits 预测位置 t+1 的真实 Token
    logps = F.log_softmax(logits[:, :-1].float(), dim=-1)
    targets = input_ids[:, 1:]
    token_logps = logps.gather(-1, targets.unsqueeze(-1)).squeeze(-1)
    mask = completion_mask[:, 1:].bool()
    return token_logps.masked_fill(~mask, 0.0).sum(dim=-1)

def dpo_loss(policy_chosen, policy_rejected,
             ref_chosen, ref_rejected, beta=0.1):
    # 每个参数均为 [B]，且同一行的 chosen/rejected 必须配对
    policy_gap = policy_chosen - policy_rejected
    ref_gap = (ref_chosen - ref_rejected).detach()
    margin = beta * (policy_gap - ref_gap)
    return -F.logsigmoid(margin).mean()

# 参考模型需冻结参数、设为 eval，并在 torch.no_grad() 下前向。
# loss.backward() 后，优化器只更新策略模型。
```

这是教学实现，会构造较大的 FP32 Log-softmax 张量；大模型训练应采用框架中经过验证的高效实现。它展示了几个不能省略的细节：

1. **只累加目标回答的 Logprobs。** Prompt 提供上下文但不直接计入回答分数；padding 不计分，回答结束标记按模板正常计分。模型前向仍需正确传入 attention mask。
2. **Next-token shift 必须正确。** 最后一个 prompt 位置的 logits 用于预测回答首 Token，mask 应跟随目标 Token 对齐。
3. **原始 DPO 使用序列 Logprob 求和。** 改成每条回答的 Token 平均会改变目标，并不是无关紧要的数值优化；长度偏差应结合数据与具体变体处理。
4. **两条分支的上下文、模板与截断规则必须一致。** 不能把 chosen 的关键结论截掉却保留 rejected，再沿用原偏好标签；也不能让两分支丢掉不同的历史消息。
5. **参考策略必须真正固定。** 使用 LoRA 时，DPO 起点若已包含 SFT adapter，直接关闭 adapter 可能退回基础模型，而不是预期的 SFT 参考策略。应保存冻结副本、参考 adapter 或正确缓存参考分数。

参考模型不求梯度，因此不需要其梯度和优化器状态；但在线重算仍需要权重与前向计算。固定参考模型和预处理后，可以预计算参考 Logprobs；模型、模板、tokenizer、截断或计分规则改变时，需要重新计算。

## 5. DPO、SFT、PPO 与 GRPO 怎么选？

| 维度 | SFT | 标准离线 DPO | 典型 LLM PPO / GRPO |
| --- | --- | --- | --- |
| 主要监督 | 问题与示范回答 | 同题 chosen / rejected 偏好对 | 当前采样回答及其奖励 |
| 更新时生成候选 | 通常不需要 | 不需要 | 通常需要，生成与更新交替 |
| 独立奖励模型 | 不需要 | 不需要 | 取决于奖励来源，也可用规则或验证器 |
| 优势估计 | 不需要 | 不需要 | PPO 常用 Critic；GRPO 用组内奖励 |
| 主要作用 | 学习任务形式与示范行为 | 利用正负对照调整相对偏好 | 在当前策略采样分布上利用奖励优化 |
| 主要瓶颈 | 示范质量和覆盖 | 偏好质量、候选覆盖和分布偏移 | 采样成本、奖励质量与策略更新稳定性 |

常见起点是 **SFT → DPO**：模型先会按任务格式回答，再用偏好对改善行为。SFT 并非 DPO 公式的强制前置步骤，但任务能力和数据分布严重不匹配时，仅靠偏好排序通常很难补齐。

已有高质量比较数据、希望先建立简单稳定的对齐基线时，DPO 很合适。数学或代码任务若有可靠验证器，并且需要持续探索新解，可以考虑[GRPO](/daily/2026/10/2026-10-20-daily-grpo)等在线训练方法。两者也可以分阶段组合；DPO 并不意味着不能提升推理能力，GRPO 也不意味着奖励必须来自人工偏好。

## 实践建议：不要只看 Loss 下降

- **先审数据，再扩大训练。** 去掉相同回答对、错标和模板污染；按 prompt 或问题族划分训练与验证，避免同题的不同候选泄漏到两侧。
- **让差异对准目标。** 如果 chosen 总是更长、更多标题，模型可能学到形式捷径。保留长度相近的对照、难负例和正常任务样本，检查 AI 评审的顺序偏差与人工一致性。
- **同时观察成对指标与绝对指标。** 看验证偏好准确率、margin、chosen/rejected 的原始 Logprobs，再看实际生成的事实正确性、任务成功率和输出长度。初始化 margin 为 0 的平局不能当成“排序错误”的证据。
- **把隐式奖励当作诊断量。** $\hat r_\theta$ 是相对固定参考的分数，不能直接当成正确率；不同参考模型或 $\beta$ 下的数值也不宜直接横比。它同样不是实际生成分布 KL 的直接测量。
- **用独立生成评估决定检查点。** 固定解码配置，与 SFT 基线比较；用人工盲评、单元测试或其他独立标准复核。偏好 margin 增大，可能同时伴随泛化下降和回答似然退化。

最后记住这条主线：**SFT 让模型模仿好答案，DPO 让模型利用好坏答案之间的差异；它简化了偏好训练的优化链路，但数据质量、分布覆盖和独立评估仍然决定模型究竟学到了什么。**
