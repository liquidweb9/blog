# RAG 答错了，问题出在哪一层？

## 一句话结论

**先找正确证据在哪一步消失，再看模型拿到证据后能不能用对。** 只看最终答案准确率，无法判断应该扩大召回、调整 Rerank、修正上下文截断，还是改生成提示词。

## 1. 问题场景：同一个错答，可能有四种原因

用户问：「促销商品签收 10 天、未拆封，还能退吗？」假设知识库里有这三段：

| 段落 | 内容 |
| --- | --- |
| `E1` | 促销商品也适用标准退货规则。 |
| `E2` | 标准退货规则：未拆封商品签收后 14 天内可申请退货。 |
| `D1` | 促销优惠券自领取之日起 7 天内有效。 |

回答这道题需要 `E1` 和 `E2`。`D1` 同时出现「促销」和一个天数，但讲的是优惠券。假设最终答案仍然引用「7 天」，诊断时依次看这四份记录：

1. **融合候选**：`E1`、`E2` 有没有进入准备交给 Rerank 的候选集？如果没有，再拆开向量、关键词和 [RRF 融合](../09/2026-09-16-daily-rrf) 各自的结果定位。
2. **重排入选**：证据在候选集里，却掉出了重排后的 Top-K？优先检查排序器、打分文本与 Top-K。
3. **实际上下文**：Top-K 里都有，拼装时却因为 Token 预算、去重或段落截断丢了关键句？这时需要查实际送给模型的内容。
4. **答案生成**：两条关键证据都在实际输入里，模型却引用了 `D1`？检查模型能否区分规则适用范围，以及答案和引用是否匹配。

这里的判定单位是**一组足以回答问题的证据**，而不是「至少召回一段相关文本」。有些问题存在多条有效证据路径；例如 `E3` 如果单独写清了促销商品的退货期限，`{E1, E2}` 和 `{E3}` 都是合格的证据组。

## 2. 先定义「证据找到了」：相关、够用、可见是三件事

把证据标在**文档版本及关键文本范围**上，再映射到当前索引的 chunk。只标 `chunk_id` 会把测试集绑在某一种切分方式上：把 512 Token 改为 256 Token 后，哪怕同一句原文依然被找到，旧 ID 也未必还在。标注还要注明规则的适用范围和生效日期；两段文字可能都与「退货」高度相关，只有其中一条是该订单适用的有效版本。

假设题目的合格证据组是 $\{E_1,E_2\}$ 或 $\{E_3\}$，我们可以同时观察三个量：

| 指标 | 回答的问题 | `Top-2 = [D1, E1]` | `Top-2 = [D1, E3]` |
| --- | --- | --- | --- |
| 任一证据命中（Hit@2） | 至少找到了一个可用证据吗？ | 是 | 是 |
| 指定证据组的段落召回率（以 `E1+E2` 为准） | 这一条解题路径找回了多少？ | 1/2 | 0/2 |
| 完整证据组命中（Complete@2） | 是否有至少一条解题路径找全了？ | 否 | 是 |

Rerank 的 MRR 可以反映第一条相关证据排得有多靠前，但不足以衡量规则组合是否找全。反过来，Complete@K 只判断证据是否齐全：把一条错误的旧规章放第一条，仍可能完全不影响该指标。因此生成侧最好另记两项：**结论和关键条件是否正确**、**每条关键主张能否被实际引用支持**。模型可以碰巧答对期限，却引用一条无关的优惠券规则；这种输出应记为「答案正确，引用不支持」，不能当成端到端的成功样本。

对于上下文阶段，`E2` 被截成「未拆封商品可申请退货」后，即使保留了同一个 ID，也不再含有决定这道题的「签收后 14 天」。最终应依据**实际发给模型的文本**重算证据可见性。如果拼装阶段还会扩展父文档、补相邻段，证据甚至可能在后面重新出现；要同时记「丢失」与「补回」，不能机械地沿着同一条漏斗计数。

下面从文档坐标出发做一次计数。证据和实际片段都记录为 `(文档版本, 起点, 终点)`，区间用左闭右开；仅在证据跨度被实际片段完整覆盖时算命中。这里假定用于拼装的是原文切片；若管线把原文改写成摘要，则需要另测摘要是否保留了原主张，不能沿用这套位置判断。

```python
policy = "未拆封商品可申请退货；申请期限为签收后14天。"
span = "签收后14天"
start = policy.index(span)
end = start + len(span)
evidence = ("standard-policy:v2", start, end)

def visible(evidence, fragments):
    doc, start, end = evidence
    return any(src == doc and lo <= start and hi >= end for src, lo, hi in fragments)

ranked = [("standard-policy:v2", 0, len(policy))]
packed = [("standard-policy:v2", 0, end - 1)]
expanded = packed + [("standard-policy:v2", start, len(policy))]
assert visible(evidence, ranked)
assert not visible(evidence, packed)
assert visible(evidence, expanded)
print("精排找到证据 → 拼装丢失证据 → 相邻片段补回证据")
```

如果关键范围拆在多个可见片段里，可以按文档坐标合并连续区间，再检查模型是否看到了完整规则。代码采用更保守的口径：至少一段要完整包含证据。无论采用哪种口径，都应在整个评估集上保持一致。

## 3. 一个最小评估：用五条记录定位首个失效点

下面是手工构造的诊断日志，用于演示计数方式。`candidates` 是融合后候选集，`selected` 是精排选中集，`context` 只记关键证据文本仍完整可见的段落。`oracle_ok` 表示给**同一个模型**直接提供人工标注的正确证据，再按同一标准评分的结果。这个小例子假设阶段间只筛掉内容，不会新增证据。

```python
# id, 合格证据组, candidates, selected, context, 实际答对, 正确证据对照答对
cases = [
    ("q1", [{"a", "b"}], {"a", "x"}, {"a"}, {"a"}, False, True),
    ("q2", [{"c"}], {"c", "x"}, {"x"}, {"x"}, False, True),
    ("q3", [{"d", "e"}], {"d", "e"}, {"d", "e"}, {"d"}, False, True),
    ("q4", [{"f"}], {"f", "x"}, {"f", "x"}, {"f", "x"}, False, False),
    ("q5", [{"g", "h"}, {"i"}], {"i", "x"}, {"i"}, {"i"}, True, True),
]

stage_names = ("候选召回", "重排入选", "上下文保留")
passed = [0, 0, 0]
actual_correct = oracle_correct = correct_with_evidence = 0

for qid, evidence_sets, candidates, selected, context, answer_ok, oracle_ok in cases:
    actual_correct += answer_ok
    oracle_correct += oracle_ok
    for idx, available in enumerate((candidates, selected, context)):
        if not any(group <= available for group in evidence_sets):
            print(f"{qid}：首个失效点是{stage_names[idx]}")
            break
        passed[idx] += 1
    else:
        correct_with_evidence += answer_ok
        print(f"{qid}：{'通过' if answer_ok else '证据齐全但答案错误'}")

print(f"候选证据齐全：{passed[0]}/{len(cases)}")
print(f"有证据的候选中，重排后仍齐全：{passed[1]}/{passed[0]}")
print(f"有证据的重排结果中，拼装后仍齐全：{passed[2]}/{passed[1]}")
print(f"实际上下文证据齐全时答对：{correct_with_evidence}/{passed[2]}")
print(f"实际答对：{actual_correct}/{len(cases)}；正确证据对照答对：{oracle_correct}/{len(cases)}")
```

| 检查点 | 样例结果 | 先查哪里 |
| --- | --- | --- |
| 候选证据齐全 | 4/5 | `q1`：是否漏索引、分块割裂，或候选深度不够 |
| 在候选齐全的题中，重排后仍齐全 | 3/4 | `q2`：精排为何把正确证据挤出 Top-K |
| 在重排齐全的题中，拼装后仍齐全 | 2/3 | `q3`：序列化、预算或截断在哪一步丢了 `e` |
| 在实际上下文齐全的题中，答案正确 | 1/2 | `q4`：给人工证据仍答错，优先查提示词、规则解释或标注 |

这里的 **3/4** 指「候选已经找全的四道题中，三道经重排仍然找全」；如果要汇报整个流水线到这一阶段的覆盖率，应报 **3/5**。尤其是比较两个召回器时，进入 Rerank 的可能是不同难度的题，不能只比较各自的条件通过率就断言 Rerank 变好了。测试两个排序器时，优先用同一份候选做逐题对照。

同样，**证据齐全时答对 1/2** 并不是生成阶段在所有题上的准确率。如果 `q1` 在证据不齐时碰巧答对，端到端得分会增加，但召回数字不会变；答案评分还应单独检查引用和关键主张，区分「有证据地答对」与「猜对」。

## 4. 正确证据对照：它能定位什么，不能说明什么？

上例实际答对 **1/5**，直接提供正确证据后答对 **4/5**。这是构造日志演示的差值，不能读成「改召回就能提升 60 个百分点」。直接提供正确证据往往同时改变了证据数量、干扰、顺序和长度。要继续追问原因，可以用同一道题做一组可回放的实验：

| 组别 | 给模型什么 | 如何解释与前一组的差异 |
| --- | --- | --- |
| A：原始上下文 | 实际送出的文本、顺序与引用 ID | 当前失败能否重现 |
| B：补缺失证据 | 保持结构和位置，用缺失证据替换长度接近、经核对无关的填充段 | B 修复错误，说明引入缺失证据在这次干预中有帮助；替换本身也改变了文字内容 |
| C：去掉干扰 | 保留 B 中证据，将其余易混规则换成近似长度的中性内容 | C 优于 B，说明模型可能受旧政策或相似规则干扰 |
| D：只给人工证据 | 仅提供足以作答的原文，不把参考答案写进去 | D 仍失败，优先核对证据标注、生成提示词和模型能否完成规则组合 |

固定模型版本、系统提示、采样配置和答案评分标准；B、C 尽量控制 Token 预算和顺序。如果记录的上下文本来就有完整证据，可以略过 B，优先做 C 或重排证据位置。人工证据对照是诊断工具，不是性能上限：它可能删除了模型原本用得上的背景，也可能漏掉另一条有效证据路径；应记录「原系统答对、对照反而答错」的题。

## 5. 怎么把诊断落到下一次迭代？

在客服知识库里，看到「证据缺失」还不能直接决定换模型。可以按下面的顺序逐步排除：

| 观察 | 下一轮只改一个变量 | 同时盯住的代价 |
| --- | --- | --- |
| 源文档有答案，索引里找不到完整关键跨度 | 修文档解析或切分；先确认标题、表头、适用条件与正文是否被拆散 | 索引体积、重复段落 |
| 关键词或向量单路能找到，融合候选丢了 | 对照各路排名，测试扩大候选池或调整融合策略 | 每题精排开销、尾延迟 |
| 候选证据完整，精排只留近义重复段 | 固定候选测试重排输入、文档多样性或按文档限额 | 单段题是否被误伤 |
| 重排完整，实际输入丢了关键条件 | 固定排序，测试段落打包、证据段长度和截断方式 | 输入 Token 数、引用文本是否还可追溯 |
| 原上下文够用，模型仍混淆新旧规则 | 固定证据比较提示词或模型，单独评估引用支持 | 拒答率、延迟、每题成本 |

发布时可以用一张**同题变化表**：旧版对新版错、旧版错新版对分别是多少。比如 30 道题里修好 5 道、弄坏 3 道，净增只有 2 道，且需要检查新的 3 个失败是否集中在关键业务场景。用同一批题还能挑出回归样本，逐条查证据在哪一层变化，而不只是看平均分。

## 6. 最小落地：先做 30 道可回放的题

1. **准备样本。** 从单段定位、多段规则组合、无答案三个场景各取 10 题，记录期望结论、合格证据组、生效版本和无答案时允许的回复。把「缺资料，应澄清」和「有明确禁止条款，应回答不能」分开标，后者仍是有证据题。
2. **冻结可回放记录。** 每题关联知识库快照、索引与模型版本，保留各路查询、候选 ID 和次序、重排分数，以及实际输入所用的文本范围和输出。调阈值和提示词时另留评估题，避免反复修同一批题导致结果失真。
3. **分三栏汇报。** 证据齐全、答案与引用、延迟与成本各自报告。在无答案题上统计应拒而未拒，在可回答题上统计应答而误拒，样本少时附上分子和分母。30 题适合发现失效模式，发布前再按真实流量的题型分布补样本。
