# 写作规则与例子设计

## 1. 整体叙事

面向希望理解并能复述方法的中文读者。方法和贡献写细，实验抓关键证据，避免把研读变成逐页翻译或一串摘要。

- 标题表达论文简称与核心问题，不直接复制长英文标题。
- 开头用一段话连起问题、关键机制、实验条件和效果；论文信息只保留标题、作者、发表、官方入口等必要项目。
- 背景只补理解本文必需的概念，首次出现的缩写与符号就地解释。
- 段落之间说明因果或数据如何承接，例如「尺度统一了，但尚未得到概率，因此下一步……」。
- 自然区分作者结果、个人分析、构造例子和研究设想。一处简短标识通常足够，不在每段反复声明。
- 不展示写作任务、工具过程、版本核稿清单、原稿目录与本地文件指纹。

## 2. 正文还是注释：判定方法

先问：**去掉这条信息，是否会改变读者对方法成立条件、实验证据或结论范围的判断？**

| 内容 | 放置方式 |
| --- | --- |
| 主版本的关键结果、任务定义、符号与推导 | 正文，必要时带简洁图表编号 |
| 条件独立、威胁模型、数据划分、oracle、转导设置、预算差异、泛化限制 | 正文相关位置，解释实际影响 |
| 构造参数与自拟案例 | 正文简短写「用一组说明性参数」或「考虑一个例子」，不伪装实测 |
| 原文逐页定位、下载记录、版本差异、文件哈希 | 相邻注释或内部来源索引 |
| 未确认的阈值搜索、初始化、截断策略等细节 | 默认注释；若改变方法解释，则正文保留简短限制 |
| 原文数字冲突或算不出的宣传比例 | 注释保留原始核对，正文改用能确认的具体结果；若冲突直接动摇核心结论，正文说明不确定性 |
| 论文官方链接、必要引文、图像署名、许可与改动说明 | 读者可见；署名可统一放文末，遵循来源实际要求 |

推荐写法：

```md
归一化将不同来源的评分映射到可比尺度，但不会自动把分数变成正确概率。

<!-- 作者自检：归一化依据主版本附录 C.1；分位数统计范围和常数分数处理待查实现，不从其他版本补齐。 -->
```

不把关键条件藏进注释，例如应在正文解释「目标批次的无标签统计参与参数估计，因此这里是转导式评估」。

HTML 注释用于避免正文和目录割裂，**不是私密存储**：源码、生成 HTML 或 RSS 中仍可能留有注释。不要放凭据、私人分享令牌或敏感信息。

## 3. 贡献逐项展开

每项贡献回答：

1. **问题与场景**：谁在什么输入和约束下做什么？
2. **已有方案卡在哪里**：定位到一个计算、状态、消息、假设或选择步骤。
3. **关键变化**：新增或改变了哪种机制？与最接近方法的差异是什么？
4. **同场景前后对照**：旧方案与新方法经过哪些不同的中间步骤？
5. **证据、代价与边界**：对应实验/定理支持什么，引入什么条件或开销？

不要把「用了某种已有算法」自动称为算法创新，也不要把整套系统提升全归于某个没有独立消融的模块。

## 4. 原图、公式与方法拆解

### 原图

- 用确实读取过的原稿提取关键图。优先总体框架和关键机制，再选真正参与分析的结果图，不凑图数。
- 图注只写原图编号和图意，详细页码、裁剪坐标和来源版本进注释或 `sources.json`。
- 解释模块、箭头、坐标轴、颜色和子图关系，沿图逐步讲输入、操作、中间产物与输出。
- 原图分离训练/推理或离线/在线时，正文也分开；图中的示意权重不能直接当作真实参数。
- PDF 文本提取不能代替图面检查。裁剪不丢轴标、图例、关键标签；保留可读性，按实际需要用 WebP/PNG/SVG。
- 自绘补图注明「根据原文整理」；尚未取得原图就标记阶段稿，不能用自绘图冒充。

### 公式与模块

按「直觉 → 符号 → 运算 → 结果含义 → 例子」展开，关键符号首次出现时交代范围、维度或单位。

每个模块尽量讲清：

```text
目的 → 输入来自哪里 → 怎样处理 → 什么保持不变/被更新
     → 中间结果形状或状态 → 输出给谁 → 为何选择这种设计
```

明确模型能看到什么、标签能用于什么，防止解释时无意加入答案泄漏。区分原文公式、等价代数展开与解释性简化。实现未披露时不凭常见做法补成官方细节。

## 5. 怎样适量增加例子

### 选例子的原则

**一个贯穿案例 + 少量难点局部例子**。是否新增，取决于它能否解决一个新的理解障碍，而不是章节数量。

- 贯穿案例：输入具体、期望输出明确，能展示原方法失败点，并让新机制走到最终输出。
- 局部数值例子：用于概率、阈值、损失或复杂度等抽象计算，尽量少量对象、可手算。
- 反例：用于解释一个假设为何必要，或为什么某个看似合理的替代方案会失败。
- 多处可以引用同一个案例，不要重复完整题面和计算表；无需解释的新常识不另举例。

### 每个例子的最小闭环

```text
要澄清的难点 → 具体输入/假设 → 旧方式的结果
             → 新机制的关键中间量 → 输出变化 → 这个例子说明什么
```

说明性参数可以假设给定，但交代真实系统如何取得它们。不要仅用三条候选就宣称学出了验证器准确率，也不要用小例子证明真实性能或泛化。

新旧方法对比适用于问题场景和对比型例子；纯计算或状态例子只需具体输入、关键中间量、结果及其含义，不必强加对照方法。

### 写法示例：为什么分数相同不代表证据相同

假设同一问题的两个候选 A、B 分别得到三个裁判的投票：A 为 `(1,1,0)`，B 为 `(0,1,1)`。计票都是两票，差别在于 A 得到了裁判 1 的支持，B 得到了裁判 3 的支持。接下来应代入**正在分析的论文实际定义的聚合规则**计算中间量；如果该论文没有可靠性建模，就不能把此例中的裁判权重硬塞进它的方法。

这展示的是「平票时缺少什么信息」的局部例子，不是任何论文的实验结论。不同论文应换成匹配自身机制的任务。

### 写法示例：把改善比例算清楚

成功率从 60% 到 75%，是增加 **15 个百分点**；相对成功率提升为 25%；错误率从 40% 到 25%，相对错误率下降为 37.5%。三者含义不同，不能混写成「提升 15%」。真实文章使用原文数据；这里仅用于内部写作校准，不必整段放进笔记。

### 按论文类型选例子

| 论文类型 | 合适例子 | 必须保留的真实约束 |
| --- | --- | --- |
| 大模型/Agent | 同题多候选、检索—重排、一次工具调用或短轨迹 | 信息可见性、生成和验证职责、评分目标 |
| 视觉/多模态 | 小图像块、少量检测框、短视频帧序列 | 张量形状、坐标系、匹配或注意力的实际规则 |
| 系统/后端 | 两三个节点、读写时序、一次故障与恢复 | 一致性模型、消息与状态、成本单位 |
| 理论/密码学 | 小规模协议消息流、假设失效的反例、玩具参数计算 | 安全定义、攻击者能力和定理条件；玩具参数不代表实际安全性 |

数值例子检查单位、维度、合法范围、概率和、代入和最终排序。只需有意义的验算，不为低影响文案改动编造测试。

## 6. 实验与理论结论

- 主要结果至少说明数据/工作负载、任务、指标方向、关键配置与比较对象；表格不必抄全。
- 区分候选覆盖上限、oracle 对照和实际可部署选择器；模型数、标签量、候选数和预算不同，不能写成同条件替代。
- 消融应对应到具体模块，说明支持哪个判断；不同设置的消融不能拼成一条曲线。
- 时间、FLOPs、显存、调用次数、价格不是同一单位；区分训练、离线预处理、在线推理与端到端成本。
- 有误差条、重复实验或跨域结果时说明其意义；没有统计证据不自行添加「显著」等结论。
- 理论论文讲清定理断言、前提、证明关键步骤、复杂度与保证范围；不强行补不存在的训练和实验。

## 7. 总结、方向和延伸阅读

总结提炼可迁移的理解，不再复述摘要。联系确实读过或可核实的已有知识，具体说它们在哪个机制上相似、目标或假设又有何差异。

后续方向选择少量值得展开的问题，每个包含：

```text
依据/局限 → 可证伪假设 → 最小修改 → 数据与基线
         → 指标与成功判据 → 成本/主要风险 → 为什么值得先做
```

研究设想不能写成已完成实验；不要只列「加大模型、更多数据、进一步优化」。

延伸阅读按前置知识、直接基线、相邻路线、真实后续工作排序，每项写阅读目的与关键问题。核实标题和链接，前置论文不能误称为后续成果。
