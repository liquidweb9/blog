# Context Engineering

> Context Engineering 研究的不是“把更多内容塞给模型”，而是如何在每个步骤为模型构造最小、充分、可信、时效明确的工作上下文。

---

## 1. Context 的组成

一次模型调用的上下文通常包含系统指令、任务目标、对话历史、当前状态、计划、工具定义、工具结果、检索证据、记忆和输出契约。它们来源不同，可信度、有效期和权限也不同。

状态是系统保存的完整事实；上下文是为当前步骤从状态和数据源中生成的视图。两者不应混为一谈。

## 2. 上下文流水线

```text
候选信息
→ 权限过滤
→ 相关性选择
→ 去重与冲突检测
→ 压缩或摘要
→ 按优先级排序
→ Token 预算分配
→ 组装并记录 provenance
```

每段上下文应尽可能携带来源、时间、版本、权限标签和可信等级。

## 3. Token 预算

预留输出和工具调用空间后，再为各类输入设置预算。建议区分：

- 不可裁剪：系统策略、当前任务和输出契约；
- 高优先级：当前状态、最近工具结果和关键证据；
- 可压缩：较早对话、长文档和重复观察；
- 可丢弃：与当前步骤无关的历史和低价值日志。

截断应以语义单元为边界，避免把 Schema、代码块或证据截成无效片段。

## 4. 历史压缩

长期对话不能只依赖滑动窗口。可同时保留：

- 最近若干轮原文；
- 经过验证的会话摘要；
- 用户明确偏好与约束；
- 未完成事项；
- 重要工具结果的引用，而非全部原文。

摘要必须与原始 Trace 建立引用关系；涉及金额、日期、身份和审批的事实不应只靠模型摘要保存。

## 5. Lost in the Middle 与排序

关键指令和当前任务应放在稳定、显著的位置。检索证据按相关性、可信度和时间排序，必要时在上下文开头提供证据目录。不要把最关键约束埋在大量工具输出中间。

## 6. 缓存与复用

稳定前缀、工具目录和只读资料可以缓存，但缓存键必须包含：

```text
tenant + permission_scope + source_version
+ prompt_version + tool_catalog_version
```

权限变化、文档更新或策略升级时需要失效。跨用户复用必须先证明数据隔离安全。

## 7. 上下文污染防护

网页、邮件、文档、工具返回和 Memory 都可能包含恶意指令或过期事实。防护措施包括：

- 标记内容来源与信任边界；
- 先做租户、权限和敏感数据过滤；
- 不让外部文本修改系统策略或工具权限；
- 对关键事实做结构化校验和多源核对；
- 低可信内容只作为线索，不能直接授权高风险动作。

## 8. Context 版本与评估

Context Builder 本身是需要版本管理的程序。Trace 应记录选择器、排序器、压缩器、摘要模型及其版本，并保存候选集与最终入选集的引用。

评估至少覆盖：

- 关键事实召回率；
- 无关信息比例；
- 冲突事实识别率；
- Token 使用量；
- 上下文构造延迟；
- 权限泄露率；
- 对最终任务成功率的贡献。

## 9. 小结

高质量上下文来自选择和治理，而不是堆积。完整数据留在状态与存储层，模型只看到当前步骤真正需要、且被允许看到的最小充分信息。

## 10. 深入理解：Context 是每轮动态编译出的工作集

Context Window 是容量限制，Context 是本轮实际输入，Memory 是可跨轮保存的信息，RAG 是从外部语料检索候选证据的机制。Context Engineering 类似编译流水线：收集候选 → 权限过滤 → 去重 → 相关性与可信度排序 → 压缩 → 按注意力位置编排 → 生成可追溯上下文。

### 10.1 分区预算

不要让所有来源竞争一个剩余 Token 数。为系统规则、输出 Schema、当前状态、最近对话、检索证据、工具描述和生成空间分别设硬/软预算。超限时优先删除低价值候选、合并重复事实、提取结构化状态，最后才压缩关键证据；原文始终保留在外部存储以便追溯。

### 10.2 选择函数

候选片段可按 `relevance × authority × freshness × task_utility - redundancy - conflict_risk` 排序。相似度只是 relevance 的代理，不能替代 ACL、时间有效性和来源权威性。对冲突片段不要静默选一个，应同时提供来源与时间，并要求模型标记冲突或触发验证。

### 10.3 压缩的损失模型

摘要会丢失否定、数字、时间、主体和不确定性。压缩结果应保存 `source_refs`、覆盖时间范围、生成版本和已知缺失，并使用问题驱动的摘要而非通用摘要。关键合同条款、代码错误和用户确认应保留原始片段。

### 10.4 Context 可观测性

每轮记录候选数量、过滤原因、最终片段、Token 分布、缓存命中、截断、引用利用率和冲突数。评估不只看检索 Recall，还要测 Context Precision、利用率、顺序敏感性、证据支撑率和单位有效 Token 带来的任务提升。
