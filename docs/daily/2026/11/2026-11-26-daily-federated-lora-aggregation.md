# 联邦 LoRA 到底该平均什么？

## 一句话结论

**如果目标是平均客户端对模型权重的实际改动，就要平均乘积 $B_iA_i$。** 分别平均 $B_i$ 和 $A_i$ 再相乘通常会引入额外误差；先对齐可以减少因子坐标不一致造成的误差，而同一轮所有客户端共享一个因子时，平均另一个因子就能精确得到目标。

## 1. 问题场景：模型更新相同，写法却不一样

假设客户端共享基座权重和 LoRA 缩放系数，以下把公共缩放系数提出，不影响比较。客户端 $i$ 的权重增量写成 $\Delta W_i = B_iA_i$。两个等权客户端的平均更新是：

$$
\overline{\Delta W}=\frac{B_1A_1+B_2A_2}{2}.
$$

但服务端如果只对两个因子分别取平均再相乘，就得到：

$$
\bar B\bar A=\frac{B_1A_1+B_2A_2+B_1A_2+B_2A_1}{4}.
$$

其中 $B_1A_2$ 和 $B_2A_1$ 是跨客户端配对；这正是「先乘后平均」和「先平均后乘」不同的地方。更容易忽略的是，**即使两个客户端的实际更新一模一样，因子也可以不同**。只要 $R$ 是正交矩阵，就有 $(B_1R)(R^\top A_1)=B_1A_1$：可以换低秩空间的坐标，而不改变对权重的实际更新。

## 2. 加权聚合的误差到底来自哪里？

设 $p_i$ 是归一化的客户端权重，$\bar B=\sum_i p_iB_i$、$\bar A=\sum_i p_iA_i$。把客户端因子写成「均值 + 偏差」，那么：

$$
\overline{\Delta W}-\bar B\bar A
=\sum_i p_i\,(B_i-\bar B)(A_i-\bar A).
$$

展开后只有两个偏差相乘的项留下；只含一侧偏差的项会被加权求和消掉。对于两个客户端、权重分别为 $p$ 和 $1-p$，进一步化为：

$$
\overline{\Delta W}-\bar B\bar A
=p(1-p)(B_1-B_2)(A_1-A_2).
$$

这给出了三个有用的判断：

- **共享一侧时，误差必然为零。** 若所有客户端使用同一个 $A$，那么 $A_i-\bar A=0$；本地的 $B_i$ 可以差得很远，平均依然精确。
- **两侧都有变化时，误差也可能碰巧为零。** 例如两客户端的 $(A_1-A_2)$ 的输出刚好落在 $(B_1-B_2)$ 的零空间。共享一侧是协议能保证的充分条件，不是唯一的数学条件。
- **只把一侧变得更像，不保证误差一定变小。** 对齐会配对改变两侧，残差取决于两个差异矩阵相乘的结果。要检查聚合后的完整更新，不能只报告因子距离。

这里讨论的是「是否忠实实现指定的加权平均」。即使聚合误差为零，若各端做了多步本地训练，也不能据此推出结果与集中式训练相同，更不能推出非 IID 数据下的任务效果一定更好。

## 3. 一个 NumPy 实验：同一份更新被平均小了一半

下面让第 2 个客户端用不同的坐标表达第 1 个客户端的更新。我们只拟合 $B$，求最接近 $B_1$ 的 $B_2Q$，再用 $Q^\top$ 配对变换 $A_2$。当 $Q^\top Q=I$ 时，展开平方距离后，和 $Q$ 有关的只剩 $-2\operatorname{tr}(Q^\top B_2^\top B_1)$；对 $B_2^\top B_1$ 做一个 $r\times r$ 的 SVD 就能得到正交解。

这是一个简化的 Procrustes 例子。[FedRot-LoRA](../../../papers/cryptography/2026-11-16-fedrot-lora) 用上一轮全局因子作参考，**按轮次选择 $A$ 或 $B$ 作为对齐目标，另一侧跟随同一旋转配对变化**。论文要求旋转的行列式为 $+1$，还会在单位阵与求得的旋转之间做插值，再投影回旋转矩阵。如果直接用插值得到的非正交矩阵 $C$ 做 $(B_iC,C^\top A_i)$，中间留下的 $CC^\top$ 可能改变客户端自己的更新。

```python
import numpy as np

B1 = np.array([[1., 0.], [0., 2.], [0., 0.]])
A1 = np.array([[1., 0., 0.], [0., 1., 0.]])
R = np.array([[0., -1.], [1., 0.]])
B2, A2 = B1 @ R, R.T @ A1

target = (B1 @ A1 + B2 @ A2) / 2
naive = ((B1 + B2) / 2) @ ((A1 + A2) / 2)

# 用 SVD 解 min_Q ||B2 @ Q - B1||_F，约束 Q.T @ Q = I。
u, _, vh = np.linalg.svd(B2.T @ B1)
Q = u @ vh
B2_aligned, A2_aligned = B2 @ Q, Q.T @ A2
assert np.allclose(B2_aligned @ A2_aligned, B2 @ A2)
aligned = ((B1 + B2_aligned) / 2) @ ((A1 + A2_aligned) / 2)

for name, update in [("直接平均因子", naive), ("对齐后平均因子", aligned), ("平均完整更新", target)]:
    print(f"{name}：对角线={np.diag(update).tolist()}，"
          f"误差={np.linalg.norm(update - target, 'fro'):.3f}")
```

```text
直接平均因子：对角线=[0.5, 1.0, 0.0]，误差=1.118
对齐后平均因子：对角线=[1.0, 2.0, 0.0]，误差=0.000
平均完整更新：对角线=[1.0, 2.0, 0.0]，误差=0.000
```

本例对齐后为零误差，是因为两个客户端的区别**只有**已知类型的坐标旋转。真实训练中，客户端可能学到的是不同方向的更新；旋转保持 $BA$ 不变，无法把不同的 $BA$ 变成同一个矩阵。这个结果说明了坐标对不齐时会发生什么，不代表对齐在每轮都能消除聚合误差。

## 4. 两个反例：尺度不对齐，以及目标的秩装不下

### 反例一：更新相同，但正交对齐也没用

更一般地，任意可逆矩阵 $S$ 都可以作配对变换 $(BS,S^{-1}A)$，而正交对齐只能覆盖其中一部分。取秩为 1 的例子：$B_2=2B_1$、$A_2=A_1/2$。两个客户端仍有 $B_2A_2=B_1A_1$，但直接平均得到 $(1.5B_1)(0.75A_1)=1.125B_1A_1$。正交变换保持因子范数，不能把 $2B_1$ 缩回 $B_1$；若进一步限制到 $\mathrm{SO}(1)$，可用变换甚至只有恒等。

### 反例二：即使先精确平均，固定秩也可能放不下

两个秩为 1 的更新分别是 `diag(1, 0)` 和 `diag(0, 1)`，等权平均得到 `diag(0.5, 0.5)`，秩为 2。任何保留秩为 1 的方案都不能精确表示它。根据截断 SVD 的最优性，本例最小 Frobenius 误差仍然是 $0.5$。如果直接平均两个秩为 1 的因子，还会产生非零的非对角元素：客户端只想各自更新一条对角线，交叉配对却写到了原本不想改的位置。

下面把两种情况放到同一个短实验里。这里的「秩 1 最优」是**误差下限**，能用来判断直接平均离同秩下最好的结果还有多远。

```python
import numpy as np

e1, e2 = np.eye(2)[:, :1], np.eye(2)[:, 1:]

def compare(label, b1, a1, b2, a2):
    target = (b1 @ a1 + b2 @ a2) / 2
    naive = ((b1 + b2) / 2) @ ((a1 + a2) / 2)
    u, s, vh = np.linalg.svd(target, full_matrices=False)
    best_rank_one = (u[:, :1] * s[:1]) @ vh[:1]
    actual_error = np.linalg.norm(naive - target, "fro")
    rank_floor = np.linalg.norm(best_rank_one - target, "fro")
    assert np.allclose(target - naive, (b1 - b2) @ (a1 - a2) / 4)
    print(f"{label}：目标秩={np.linalg.matrix_rank(target)}，"
          f"因子平均误差={actual_error:.3f}，秩 1 误差下限={rank_floor:.3f}")

compare("仅尺度不同", e1, e1.T, 2 * e1, e1.T / 2)
compare("更新方向不同", e1, e1.T, e2, e2.T)
```

```text
仅尺度不同：目标秩=1，因子平均误差=0.125，秩 1 误差下限=0.000
更新方向不同：目标秩=2，因子平均误差=0.500，秩 1 误差下限=0.500
```

第二行的两个误差恰好相等，不意味着矩阵相等，也不证明因子平均通常最优。这里两个奇异值相同，最优的秩 1 近似方向不唯一；代码里的截断 SVD 选一个方向，因子平均碰巧选了另一个同样好的方向。要判断效果，还要看模型任务关心的是哪个方向。

## 5. 三种聚合路线，分别换来了什么？

**共享一个因子时，乘积对另一个因子是线性的。** 如果同一轮所有客户端使用同一个固定 $A$，那么 $\sum_i p_i B_i A = (\sum_i p_i B_i) A$，固定 $B$ 的情况同理。[RoLoRA](../../../papers/cryptography/2026-11-02-rolora) 在通信轮次间切换训练哪一侧，因此每轮都能利用这个等式，同时让两个因子在不同轮次都有机会变化。仅仅让每个客户端在本地交替训练两侧，如果上传时两侧都因客户端而异，就没有这个保证。这也是把 RoLoRA 与 [LA-LoRA 的本地交替](../../../papers/cryptography/2026-11-02-la-lora) 放在一起读时最值得记住的区别。

**精确平均完整更新，也不一定要传稠密矩阵。** 把 $\sqrt{p_i}B_i$ 按列拼在一起得到 $B_{\mathrm{cat}}$，把 $\sqrt{p_i}A_i$ 按行堆起来得到 $A_{\mathrm{cat}}$：

$$
B_{\mathrm{cat}} A_{\mathrm{cat}}=\sum_i p_i B_i A_i.
$$

拼接后的每一块仍对应同一客户端，没有交叉配对，但中间维度从 $r$ 变成了 $Nr$（$N$ 为同秩客户端数）。如果服务器能访问各客户端因子，可以对 $B_{\mathrm{cat}}$ 与 $A_{\mathrm{cat}}^\top$ 分别做经济型 QR，把 SVD 移到两个上三角（或梯形）因子的乘积上，再还原截断后的左右因子。当 $Nr$ 远小于权重矩阵的行、列维度时，这样不必显式构造稠密目标；客户端多、$Nr$ 上来之后，服务器侧内存和分解成本仍需要实测。如果协议只暴露因子的安全求和结果，服务器不能直接做这种逐端拼接。

| 路线 | 本地训练与上传 | 对本轮实际更新的保证 | 代价或前提 |
| --- | --- | --- | --- |
| 对齐后平均因子 | 两侧都可训练，上传两侧 | 可能减少表示差异带来的误差，通常不精确 | 需要参考因子和对齐步骤，秩保持不变 |
| 共享一侧，平均另一侧 | 本轮只训练和上传活动因子 | 对本轮产生的更新精确 | 共享因子限制本轮可更新的方向；交替轮次使两侧都能学习 |
| 拼接后平均，再截断 | 两侧上传，服务器保留配对 | 截断前精确；截断后是同秩下 Frobenius 意义的最优近似 | 服务器要访问配对因子；临时秩和分解成本增长 |

这里的比较默认公共基座、权重系数口径一致。若不同客户端的秩或 LoRA 缩放不同，先把各自的实际缩放纳入 $\Delta W_i$ 再确定比较目标；直接把形状凑齐，并不会自动让平均有意义。

## 6. 实践建议：先用一层权重做诊断

1. **冻结一轮本地结果**：保存同一层的各端因子、缩放与权重，在同一批因子上重放直接平均和对齐后平均。这样能把「换了聚合表示」与「换了本地训练」分开；RoLoRA 这类改变训练协议的方法应另跑完整训练，不能事后由同一批因子模拟。
2. **把误差下限放在同一张表里**：以完整更新平均为对照，报告两种聚合误差和同秩截断误差。若对齐误差仍远高于截断下限，说明表示或聚合规则还有空间；若已接近下限，继续优化对齐最多只能动很小一部分，不妨评估提高输出秩。跨层比较时可补报相对误差，目标范数接近零时同时保留绝对误差。
3. **按通信预算比较训练方法**：除了每轮字节数，报告达到相似任务指标的累计字节数、服务器分解开销与本地训练时间。同样跑 100 轮，不代表上传一侧和两侧用了相同预算；更小的矩阵误差也不保证下一轮训练或下游指标更好。
