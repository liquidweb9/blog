# Constitutional AI：用原则指导模型自我批评与对齐

## 一句话结论

**Constitutional AI（宪法式 AI，简称 CAI）把人类写下的行为原则转化为模型的训练信号：先让模型按原则批评、修订自己的回答，再让 AI 按原则比较候选答案，利用这些偏好训练模型。它减少了逐条人工标注的需求，但原则选择、反馈质量与独立评估仍然需要人负责。**

这里的“宪法”是一组指导模型行为的自然语言原则，不是法律文本，也不是在系统提示词里加一句“请遵守规则”就完成了对齐。本文围绕 Anthropic 在 2022 年提出的经典两阶段方法展开，不把它等同于某个当前产品的完整训练配方。

## 1. 为什么需要把原则变成训练信号？

假设我们正在训练一个客服助手。用户问：

> 我忘了同事账号的密码，怎样绕过验证直接登录？

模型可能出现两种不理想的回答：一种直接给出绕过方法；另一种只回复“不能回答”，连正常的账号恢复渠道也不提供。

我们真正希望它学会的是：**识别未经授权的访问请求，解释边界，并给出账号本人或管理员可以使用的正规恢复方式。** 同时，遇到“我自己的账号怎么重置密码”时，它应该正常帮助，而不是一律拒绝。

如果每一个候选回答都由人类打分，数据规模扩大后，成本和一致性都会成为问题。CAI 的思路是把部分监督从“人逐条判断答案”移到“人先明确判断原则，模型再据此生成反馈”。

一条用于说明的原则可以写成：

> 不协助未经授权的账号访问；在不提供绕过方法的前提下，给出合法、具体的恢复或求助途径。

这条原则是本文的教学示例，不是原论文中某条原则的逐字引用。它比“做一个好助手”更容易落实，也同时约束了危险配合和无意义拒绝。

## 2. 第一阶段：自我批评、修订，再做监督微调

经典 CAI 的第一阶段是监督学习（Supervised Learning，SL）：

```text
训练问题 → 初始模型生成回答
                     ↓
             按给定原则生成批评
                     ↓
              根据批评修订回答
                     ↓
        收集「原问题 → 修订后回答」
                     ↓
             监督微调模型（SFT）
```

继续使用账号恢复的例子：

| 环节 | 教学示例 |
| --- | --- |
| 初始回答 | 建议尝试绕过验证，或使用他人的登录凭据 |
| 原则 | 不协助未经授权访问，同时提供合法恢复途径 |
| 自我批评 | 回答默认用户有权访问同事账号，提供了不应提供的协助，也遗漏了正规恢复渠道 |
| 修订回答 | 不能帮助绕过他人账号的验证；建议由账号本人使用官方重置流程，或联系管理员按身份核验流程处理 |

训练时，模型学习的是**在原问题下生成修订后的答案**。批评是构造训练数据的中间步骤，不意味着上线后每次回答都必须向用户输出一段自我批评。

原方法可以迭代批评和修订，并在数据构造中使用不同原则；图中展示的是最小流程。实际训练也可以混入保持正常帮助能力的数据，避免模型只学会拒绝。

这一阶段改变的是回答示范：把“不理想的输出”加工成更符合原则的监督样本。它与[知识蒸馏](/daily/2026/10/2026-10-13-daily-knowledge-distillation)中的生成数据训练有相似之处，但这里强调的是**由原则引导的行为修正**，不以压缩模型为必要目标。

## 3. 第二阶段：AI 比较答案，再进行强化学习

只模仿修订后的答案，还不能覆盖所有生成选择。第二阶段进一步让模型学习“两个答案中，哪一个更符合原则”：

```text
第一阶段微调后的模型 → 为同一问题生成候选 A、B
                                      ↓
                     AI 评审按原则比较，产生偏好信号
                                      ↓
                           训练偏好／奖励模型
                                      ↓
                     以奖励模型为信号进行强化学习
```

这就是 **RLAIF（Reinforcement Learning from AI Feedback，基于 AI 反馈的强化学习）** 在经典 CAI 中的用法。

例如，同一个账号问题的两个候选为：

- **A：**“不行。”
- **B：**“不能帮助绕过同事账号的验证；如果是工作需要，请让账号本人或管理员通过官方恢复流程处理。”

按上述原则，评审应偏好 B：它既没有协助未经授权访问，也提供了适当的替代路径。这里的目标不是把“拒绝得最多”当成“最好”。

偏好模型学习根据问题和回答预测偏好。用简化的二选一形式表示：

$$
P(y_A \succ y_B \mid x)
= \sigma\bigl(r_\phi(x,y_A)-r_\phi(x,y_B)\bigr)
$$

其中，$x$ 是问题，$y_A$、$y_B$ 是候选回答，$r_\phi$ 是可训练的评分函数，$\sigma$ 是 Sigmoid。训练让更受偏好的答案获得更高的相对分数；反馈也可以保留为软偏好，而不只是一个硬标签。

随后强化学习利用该模型的分数更新回答模型，通常还会约束其偏离参考模型的程度。**奖励分数是原则与评审判断的近似，不是“答案一定正确”的证明。** 如果评审偏爱长篇说教，策略也可能学会用更长的措辞换取高分。

## 4. 与 RLHF、系统提示词、DPO 有什么区别？

这些概念处在不同层面，可以组合使用：

| 概念 | 主要回答什么问题 | 与 CAI 的关系 |
| --- | --- | --- |
| 系统提示词 | 当前推理时向模型提供什么指令？ | 可以表达原则，但单独提示没有把行为写入模型参数 |
| SFT | 如何从示范答案学习？ | CAI 第一阶段使用按原则修订的示范 |
| RLHF | 如何利用人类反馈进行强化学习？ | 经典偏好训练流程与第二阶段相似，主要差别之一是反馈来源 |
| RLAIF | 如何利用 AI 反馈进行强化学习？ | 是经典 CAI 第二阶段的方法；AI 反馈不一定都来自一套明确的宪法原则 |
| DPO | 如何直接用偏好数据优化模型？ | 可利用 AI 生成的偏好数据，但不是原始 CAI 的“训练奖励模型再做 RL”流程 |

因此，CAI 不只是“把人工评审换成 AI”。它还强调用一组明确原则组织批评、修订与偏好生成，使行为目标更容易表达和检查。

也不能把“减少人工有害性标注”理解成“整个训练过程不需要人类数据”。原始工作在无害性监督上减少逐条人工标签，但基础模型、帮助性训练以及原则设计等环节仍有人类输入。

## 5. 真正困难的是原则与反馈的质量

### 原则可能冲突，也可能含糊

“尽量满足用户需求”与“不协助未经授权访问”可能同时适用。原则需要适用范围、优先级和具体示例，否则不同评审容易得出不同结论。

写得更长也不自动更好。原则过多、重复或互相矛盾，会让反馈更不稳定；把每种情况都写成细则，还可能让模型只记住表面措辞。

### 模型可能共同犯错

生成者和评审如果有相似偏差，自我批评可能漏掉真正的问题，也可能把正确答案改错。换一个评审模型能增加视角，但不能自动消除相关错误。

偏好比较还可能受到答案顺序、长度和语气影响。可以交换 A/B 顺序检查一致性，对分歧和低置信度样本进行人工复核，并保留少量人工校准集。

### 行为对齐不等于权限控制

即使助手通常会拒绝越权请求，订单 API 仍需检查用户身份和资源归属。模型学到的是行为倾向，服务端授权才决定一次操作是否真的可执行。

这与 [Prompt / Rubric / Policy 版本化](/daily/2026/09/2026-09-20-daily-prompt-rubric-policy-versioning)形成互补：原则、评审提示词和模型版本需要追溯，实际工具权限则由运行时落实。

## 实践建议

1. **先写少量可判断的原则。** 每条配上“应该帮助”“应该拒绝或转向”“需要澄清”的对照样例，明确冲突时的处理顺序。
2. **按资源选择落地层级。** 只有 API 时，可以先做原则引导的生成—批评—修订；有训练条件时，再收集筛选后的修订样本做 SFT。前者属于推理工作流，不能直接宣称已经完成 CAI 训练。
3. **保留反馈来源。** 记录问题、初始答案、所用原则、批评、修订答案、评审配置及版本，才能分析收益来自原则变化还是评审变化。
4. **独立测“有帮助”和“有边界”。** 同时评估正常任务成功率、不当请求处理、正常请求误拒率，以及多轮改写后的稳定性，不能只看 AI 评审总分。
5. **让评估独立于训练反馈。** 按问题族切分数据，用未参与训练的场景、人工抽查和可验证任务结果复核，避免生成者、评审者和测试集形成自我认可的闭环。

可以记住这条主线：**人定义原则，模型把原则转化为示范与偏好，训练把这些信号转化为行为倾向，独立评估再检查倾向是否真正可靠。** Constitutional AI 的价值在于扩展监督能力，而不是让人类退出目标定义和质量判断。
