# RAG 答错了，问题出在哪一层？

## 一句话结论

**先找正确证据在哪一步消失，再看模型拿到证据后能不能用对。** 只看最终答案准确率，无法判断应该扩大召回、调整 Rerank、修正上下文截断，还是改生成提示词。

## 1. 问题场景：同一个错答，可能有四种原因

用户问：「促销商品签收 10 天、未拆封，还能退吗？」假设知识库里有这三段：

| 段落 | 内容 |
| --- | --- |
| `E1` | 促销商品也适用标准退货规则。 |
| `E2` | 标准退货规则：未拆封商品签收后 14 天内可申请退货。 |
| `D1` | 促销优惠券自领取之日起 7 天内有效。 |

回答这道题需要 `E1` 和 `E2`。`D1` 同时出现「促销」和一个天数，但讲的是优惠券。假设最终答案仍然引用「7 天」，诊断时依次看这四份记录：

1. **融合候选**：`E1`、`E2` 有没有进入准备交给 Rerank 的候选集？如果没有，再拆开向量、关键词和 [RRF 融合](../09/2026-09-16-daily-rrf) 各自的结果定位。
2. **重排入选**：证据在候选集里，却掉出了重排后的 Top-K？优先检查排序器、打分文本与 Top-K。
3. **实际上下文**：Top-K 里都有，拼装时却因为 Token 预算、去重或段落截断丢了关键句？这时需要查实际送给模型的内容。
4. **答案生成**：两条关键证据都在实际输入里，模型却引用了 `D1`？检查模型能否区分规则适用范围，以及答案和引用是否匹配。

这里的判定单位是**一组足以回答问题的证据**，而不是「至少召回一段相关文本」。有些问题存在多条有效证据路径；例如 `E3` 如果单独写清了促销商品的退货期限，`{E1, E2}` 和 `{E3}` 都是合格的证据组。

## 2. 一个最小评估：用五条记录定位首个失效点

下面是手工构造的诊断日志，用于演示计数方式。`candidates` 是融合后候选集，`selected` 是精排选中集，`context` 只记关键证据文本仍完整可见的段落。`oracle_ok` 表示给**同一个模型**直接提供人工标注的正确证据，再按同一标准评分的结果。

```python
# id, 合格证据组, candidates, selected, context, 实际答对, 正确证据对照答对
cases = [
    ("q1", [{"a", "b"}], {"a", "x"}, {"a"}, {"a"}, False, True),
    ("q2", [{"c"}], {"c", "x"}, {"x"}, {"x"}, False, True),
    ("q3", [{"d", "e"}], {"d", "e"}, {"d", "e"}, {"d"}, False, True),
    ("q4", [{"f"}], {"f", "x"}, {"f", "x"}, {"f", "x"}, False, False),
    ("q5", [{"g", "h"}, {"i"}], {"i", "x"}, {"i"}, {"i"}, True, True),
]

stage_names = ("候选召回", "重排入选", "上下文保留")
passed = [0, 0, 0]
actual_correct = oracle_correct = correct_with_evidence = 0

for qid, evidence_sets, candidates, selected, context, answer_ok, oracle_ok in cases:
    actual_correct += answer_ok
    oracle_correct += oracle_ok
    for idx, available in enumerate((candidates, selected, context)):
        if not any(group <= available for group in evidence_sets):
            print(f"{qid}：首个失效点是{stage_names[idx]}")
            break
        passed[idx] += 1
    else:
        correct_with_evidence += answer_ok
        print(f"{qid}：{'通过' if answer_ok else '证据齐全但答案错误'}")

print(f"候选证据齐全：{passed[0]}/{len(cases)}")
print(f"有证据的候选中，重排后仍齐全：{passed[1]}/{passed[0]}")
print(f"有证据的重排结果中，拼装后仍齐全：{passed[2]}/{passed[1]}")
print(f"实际上下文证据齐全时答对：{correct_with_evidence}/{passed[2]}")
print(f"实际答对：{actual_correct}/{len(cases)}；正确证据对照答对：{oracle_correct}/{len(cases)}")
```

| 检查点 | 样例结果 | 先查哪里 |
| --- | --- | --- |
| 候选证据齐全 | 4/5 | `q1`：是否漏索引、分块割裂，或候选深度不够 |
| 在候选齐全的题中，重排后仍齐全 | 3/4 | `q2`：精排为何把正确证据挤出 Top-K |
| 在重排齐全的题中，拼装后仍齐全 | 2/3 | `q3`：序列化、预算或截断在哪一步丢了 `e` |
| 在实际上下文齐全的题中，答案正确 | 1/2 | `q4`：给人工证据仍答错，优先查提示词、规则解释或标注 |

实际答对 **1/5**，直接提供正确证据后答对 **4/5**。这说明在这五条假设记录里，补齐证据能帮助部分题目；**它不等于换一个召回器就能从 20% 涨到 80%**。人工证据对照往往同时移除了干扰段落、改变了顺序和长度。想区分「缺证据」和「有干扰」，可以再做一轮对照：保留原上下文，在相同预算内只替换一段无关内容为缺失证据，观察答案是否改善。

## 3. 实践建议：先从 30 道题开始

1. **按题型标注。** 从单段定位、多段规则组合、无答案三个场景各取 10 题，记录期望答案、关键证据和知识库版本。无答案题单独看拒答或澄清是否正确，不纳入「证据齐全」统计。
2. **记录可回放的数据。** 保存查询、候选 ID 与顺序、重排结果、实际上下文和模型输出。长段落只剩标题也可能保有同一个 ID，所以对被截断的输入要检查关键句或原文范围。
3. **每次只换一个变量。** 例如固定候选与生成配置，只换 Rerank；同时看 `3/4` 这样的条件通过率、端到端正确率和新增延迟。样本少时附上分子与分母，避免一个百分比掩盖变化只来自一两道题。
