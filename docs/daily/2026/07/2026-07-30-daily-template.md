# 如何使用「每日技术」文章模板

## 一句话结论

复制本文提供的模板，确定一个足够小的技术主题，再依次写完“结论、问题、示例、建议和延伸阅读”，就可以得到一篇结构完整的短文。

## 为什么需要统一模板

每日更新最容易遇到的困难，不是没有内容，而是每次都要重新考虑文章结构。统一模板可以降低写作成本，也能让读者快速判断文章是否值得继续阅读。

一篇「每日技术」只解决一个明确的问题。例如：

- 为什么数据库索引没有生效？
- JavaScript 事件循环如何处理微任务？
- RAG 为什么会召回不相关的内容？

“完整介绍 MySQL”这类主题范围太大，更适合拆成多篇文章。

## 文章模板

新建文章时，可以复制下面的内容：

```md
---
title: 文章标题
date: YYYY-MM-DD
tags:
  - 标签一
  - 标签二
description: 用一句话概括文章解决的问题。
---

# 文章标题

## 一句话结论

先用一两句话直接回答文章标题提出的问题。

## 问题与场景

说明这个问题通常在什么情况下出现，以及为什么值得关注。

## 一个具体例子

使用代码、命令、图示或真实场景解释核心概念。

## 实践建议

列出读者可以直接执行的建议，并说明适用条件和常见误区。

## 延伸阅读

- 相关文档或站内文章
```

## Frontmatter 字段说明

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 文章标题，尽量直接描述要解决的问题 |
| `date` | 是 | 发布日期，使用 `YYYY-MM-DD` 格式 |
| `tags` | 是 | 建议填写 1～3 个稳定、可复用的标签 |
| `description` | 是 | 用于文章列表和搜索结果的简短摘要 |

标签应尽量复用已有分类。与其同时使用“AI Agent”“智能体”“Agent 技术”三个相近标签，不如统一使用 `Agent`。

## 文件应该放在哪里

文章按“年份／月份”保存，文件名以日期开头：

```text
docs/daily/
└─ 2026/
   └─ 07/
      └─ 2026-07-30-daily-template.md
```

推荐的文件命名格式是：

```text
YYYY-MM-DD-topic-slug.md
```

其中 `topic-slug` 使用简短的英文小写单词和连字符。这样可以避免文件重名，文章数量增加后也容易查找。

## 发布一篇新文章

1. 在对应的年份和月份目录中创建 Markdown 文件。
2. 复制模板，填写标题、日期、标签和摘要。
3. 在专栏首页的“最新文章”中加入新文章。
4. 在归档页对应月份下加入文章链接。
5. 在标签页的相应分类下加入文章链接。
6. 本地运行 `npm run docs:dev` 预览，再运行 `npm run docs:build` 检查构建。

专栏首页建议只保留最近 10～20 篇。文章超出这个范围后，只需要从首页移除，归档页和标签页中的链接继续保留。

## 写作检查清单

- 标题是否只讨论一个具体问题？
- 开头是否直接给出了结论？
- 是否至少包含一个具体例子？
- 建议是否说明了适用条件？
- 标签是否复用了已有分类？
- 所有站内链接是否可以访问？

完成这些检查，一篇新的「每日技术」文章就可以发布了。
