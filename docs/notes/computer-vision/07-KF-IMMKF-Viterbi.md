# KF、IMM-KF和Viterbi

## 1. 算法在追踪系统中的定位

按照在追踪系统中负责的功能，这三个算法分别属于不同的层次：

```
追踪系统分层架构:

┌──────────────────────────────────────────┐
│  观测层：目标在哪里？                      │
│  YOLO / RT-DETR / TrackNet / CoTracker   │
└──────────────────┬───────────────────────┘
                   ↓
┌──────────────────────────────────────────┐
│  运动预测层：下一帧可能在哪里？              │
│  卡尔曼滤波 (KF) / IMM-KF                │  ← 本文范围
│  物理运动模型 / 光流预测                   │
└──────────────────┬───────────────────────┘
                   ↓
┌──────────────────────────────────────────┐
│  数据关联层：哪个检测属于哪条轨迹？          │
│  IoU匹配 / 匈牙利算法 / ByteTrack         │
└──────────────────┬───────────────────────┘
                   ↓
┌──────────────────────────────────────────┐
│  全局轨迹优化层：整段轨迹怎样最合理？         │
│  Viterbi / 动态规划 / 图优化              │  ← 本文范围
│  轨迹平滑 / 轨迹补全                       │
└──────────────────────────────────────────┘
```

这篇文章聚焦于运动预测层（KF + IMM-KF）和全局优化层（Viterbi）的算法原理与工程实践。

## 2. 卡尔曼滤波 (KF)

### 2.1 解决的问题

"如何在带噪声的观测中持续估计目标的实时状态？"

在追踪中的应用场景：检测器输出的球位置存在抖动和漏检，KF 利用运动连续性在观测缺失时仍能给出预测位置，在有观测时将预测和检测结果融合得到更平滑的估计。

关键认知：**KF 不是检测器，也不是完整追踪器，而是状态估计器。**它不判断候选框哪个是真球，也不做数据关联——它只负责根据历史状态和当前观测来估计目标的最可能状态。

### 2.2 基本原理

KF 的核心是一个递归的预测-更新循环：

```
初始化: 状态 x0, 协方差 P0

FOR 每一帧 t:
  ┌─ 预测步骤 ──────────────────────┐
  │ x̂ₜ|ₜ₋₁ = F · x̂ₜ₋₁                │  ← 状态转移：上一时刻状态按运动模型前推
  │ Pₜ|ₜ₋₁ = F · Pₜ₋₁ · Fᵀ + Q      │  ← 误差传播：协方差按运动模型扩展 + 过程噪声
  └──────────────────────────────────┘
  │
  ↓ 有观测 zₜ 时:
  ┌─ 更新步骤 ──────────────────────┐
  │ K = Pₜ|ₜ₋₁ · Hᵀ · (H·Pₜ|ₜ₋₁·Hᵀ + R)⁻¹│ ← 卡尔曼增益：权衡预测 vs 观测
  │ x̂ₜ = x̂ₜ|ₜ₋₁ + K · (zₜ - H·x̂ₜ|ₜ₋₁)      │ ← 状态更新：融合预测和观测
  │ Pₜ = (I - K·H) · Pₜ|ₜ₋₁                  │ ← 协方差更新：不确定性降低
  └─────────────────────────────────────────┘
```

**状态向量定义**（以足球追踪为例）：
```
基础版本:
  x = [x, y, vx, vy]           ← 位置 + 速度 (4维)

扩展版本:
  x = [x, y, w, h, vx, vy]      ← 位置 + 尺寸 + 速度 (6维)

完整版本:
  x = [x, y, w, h, vx, vy, ax, ay]  ← 位置 + 尺寸 + 速度 + 加速度 (8维)
```

**关键矩阵**：

| 矩阵 | 名称 | 含义 | 对追踪的影响 |
|------|------|------|------------|
| F | 状态转移矩阵 | 状态如何随时间演化 | 定义了运动模型 (匀速/匀加速) |
| H | 观测矩阵 | 如何从状态得到观测 | 通常只提取位置分量 |
| Q | 过程噪声协方差 | 运动模型的不确定性 | Q 越大 → 越依赖观测，轨迹越不光滑 |
| R | 观测噪声协方差 | 检测器的测量误差 | R 越大 → 越依赖预测，响应越慢 |
| K | 卡尔曼增益 | 预测 vs 观测的信任权重 | 核心变量，由 Q/R 决定 |
| P | 状态协方差 | 估计的不确定性 | P 大 → 不确定 → K 大 → 更信观测 |

### 2.3 KF 的核心假设与局限性

KF 基于几个强假设：
1. **线性系统**：状态转移和观测都是线性的（F 和 H 是常矩阵）
2. **高斯噪声**：过程和观测噪声都服从高斯分布
3. **一阶马尔可夫**：当前状态仅依赖于上一时刻的状态

足球追踪中这些假设被违反的典型场景：
- 球的急转弯/碰撞 → 线性假设被违反（实际运动是非线性的）
- 镜头切换 → 马尔可夫假设被违反（场景完全变化，历史状态无意义）
- 检测器的误检 → 高斯噪声假设被违反（偶尔的严重误检不是高斯分布能描述的）

### 2.4 KF 的优点与缺点

| 优点 | 缺点 |
|------|------|
| 计算量极小（几次矩阵乘法） | 默认线性、高斯假设，非线性场景失效 |
| 可解释性强 | 球急转、碰撞、镜头切换时预测失效 |
| 实现简单，实现代码不到 50 行 | 不能自行判断哪个候选框是真球 |
| 可平滑检测抖动 | 复杂运动模式（急加减速）下单个 KF 不够 |
| 短时间漏检时可以预测 | 长期遮挡时发散严重 |

## 3. IMM-KF (交互多模型卡尔曼滤波)

### 3.1 解决的问题

"单一运动模型无法覆盖目标的所有运动模式怎么办？"

足球不是始终遵循一种运动模式——它会匀速滚动、突然加速（被踢）、高速飞行（长传）、急速转向（碰撞）、近似静止（定位球）。单一的匀速/匀加速 KF 无法在所有模式下都表现良好。

### 3.2 核心思想

并行维护多个 KF 实例，每个使用不同的运动模型，模型之间按照马尔可夫转移矩阵动态切换：

```
模型1: KF_匀速 (CV)         - 概率 p₁  ← 适合滚地、平稳传球
模型2: KF_匀加速 (CA)       - 概率 p₂  ← 适合踢球加速、减速
模型3: KF_高机动             - 概率 p₃  ← 适合碰撞、急转向
模型4: KF_近似静止           - 概率 p₄  ← 适合定位球、死球

模型概率矩阵 M (马尔可夫转移):
  M[i][j] = P(从模型i 切换到 模型j)

IMM-KF 并不在模型之间"硬切换"，而是使用"软切换"：
模型概率是连续变化的（由贝叶斯公式更新），
融合结果按概率加权：
  x̂ = Σᵢ pᵢ · x̂ᵢ
  P̂ = Σᵢ pᵢ · (Pᵢ + (x̂ᵢ - x̂)(x̂ᵢ - x̂)ᵀ)
```

### 3.3 每一帧的处理步骤

```
步骤1: 模型交互 (Mixing)
  根据上一时刻的模型概率和转移矩阵，
  计算每个模型在当前时刻的混合初始状态
  
  模型j的混合输入:
  x̂₀ⱼ = Σᵢ p_{i|j} · x̂ᵢ
  (p_{i|j} = M[i][j] · pᵢ / (Σₖ M[k][j] · pₖ))

步骤2: 模型条件滤波 (Mode-matched Filtering)
  每个模型独立执行标准的 KF 预测和更新
  
  对每个模型 j:
  预测: x̂ⱼ⁻ = Fⱼ · x̂₀ⱼ,  Pⱼ⁻ = Fⱼ · P₀ⱼ · Fⱼᵀ + Qⱼ
  更新: x̂ⱼ = x̂ⱼ⁻ + Kⱼ·(z - Hⱼ·x̂ⱼ⁻),  Pⱼ = (I - KⱼHⱼ)·Pⱼ⁻

步骤3: 模型概率更新 (Model Probability Update)
  计算每个模型的似然（观测在该模型下出现的概率）
  用贝叶斯公式更新模型概率 pⱼ

  似然: Lⱼ = N(z - Hⱼ·x̂ⱼ⁻;  0,  Hⱼ·Pⱼ⁻·Hⱼᵀ + R)
  概率: pⱼ = Lⱼ · Σᵢ M[i][j] · pᵢ⁻ / (归一化常数)

步骤4: 估计融合 (Combination)
  按概率加权融合所有模型的状态估计
  
  x̂ = Σⱼ pⱼ · x̂ⱼ
  P = Σⱼ pⱼ · (Pⱼ + (x̂ⱼ - x̂)(x̂ⱼ - x̂)ᵀ)
```

### 3.4 软切换的优势

IMM-KF 的精妙之处在于"软切换"——模型概率是连续变化的：

```
场景: 球从匀速运动(传球) → 被踢加速 → 高速飞行

时间轴  ───●───●───●───●───●───●───●───●───
状态:     匀速  匀速  加速  加速  加速  高速  高速

模型概率变化 (软切换):
p₁(CV):   0.9  0.8  0.3  0.1  0.05 0.0  0.0
p₂(CA):   0.1  0.2  0.6  0.7  0.6  0.4  0.3
p₃(高机动):0.0  0.0  0.1  0.2  0.35 0.6  0.7

状态估计 = 平滑过渡 (融合)
```

硬切换在切换瞬间会导致状态跳变，而软切换通过连续的概率权重确保了状态估计的平滑性。

### 3.5 优缺点

| 优点 | 缺点 |
|------|------|
| 比单一 KF 更适合多运动状态场景 | 模型数量和参数需要人工设定 |
| 软切换确保状态平滑过渡 | 计算量随模型数量线性增长 |
| 能处理匀速、加速、减速之间的切换 | 无法解决检测器持续误检 |
| 仍具有一定可解释性 | 镜头切换时仍需单独重置 |
| 同时维护多个假设 → 鲁棒性强 | 转移矩阵 M 和 Q 矩阵需要合理初始化 |

## 4. Viterbi 算法

### 4.1 解决的问题

"在所有帧的候选检测中寻找全局最优轨迹"

传统的逐帧贪心匹配（选每帧最高分的候选 → 连接）的致命问题：一旦选错，后续所有决策都建立在错误基础上，无法回头纠正。Viterbi 通过比较从第一帧到最后一帧的所有可能路径，找到全局最合理的轨迹。

### 4.2 算法起源

Viterbi 算法起源于通信领域（1967年，用于卷积码解码），但在追踪中被"迁移"过来用于求解全局最优轨迹。两者的本质是一致的：在一条序列中，找到给定观测（检测器输出）下最可能的状态序列（真实轨迹）。

### 4.3 基本思想

```
候选图构建:

帧1: [候选A, 候选B, 候选C]  ← 每个候选是一个节点
帧2: [候选D, 候选E]
帧3: [候选F, 候选G, 候选H]
...
帧T: [候选X, 候选Y]

节点代价 = 该候选是真实目标的可信度
  包含: 检测置信度 + 外观置信度 + 可见性置信度

边代价 = 从前一帧候选过渡到当前帧候选的合理性
  包含: 位移大小 + 速度变化 + 方向变化 + 光流一致性

Viterbi 寻找: 整段视频中总代价最优的路径
```

### 4.4 动态规划求解

```
定义:
  dp[t][j] = 到达 帧t 候选j 的最小累积代价
  node_cost[t][j] = 帧t 候选j 的节点代价
  edge_cost[t-1][i][j] = 从 帧t-1 候选i 到 帧t 候选j 的转移代价

初始化:
  dp[1][j] = node_cost[1][j]    (第一帧只有节点代价)

递推 (t = 2, 3, ..., T):
  dp[t][j] = node_cost[t][j]
           + minᵢ { dp[t-1][i] + edge_cost[t-1][i][j] }
  
  prev[t][j] = argminᵢ { dp[t-1][i] + edge_cost[t-1][i][j] }
  (记录最佳前驱，用于回溯)

终止:
  最优路径终点 = argminⱼ dp[T][j]

回溯:
  从终点沿 prev 指针回溯到第一帧 → 得到完整轨迹
```

### 4.5 节点代价与边代价设计

这是 Viterbi 系统中最需要工程经验的环节。

**节点代价**（这个候选有多像是真实目标）：
```
node_cost = w₁ × (1 - 检测置信度)
          + w₂ × (1 - 外观模型评分)
          + w₃ × (1 - 可见性分数)
          + w₄ × 热图非匹配惩罚
```

**边代价**（两个候选之间的运动有多合理）：
```
edge_cost = w₅ × 位移惩罚       ← 不应超过最大可能速度
          + w₆ × 速度变化惩罚     ← 不应出现剧烈加速度
          + w₇ × 方向变化惩罚     ← 运动方向应连续
          + w₈ × 物理不一致惩罚   ← 如不符合抛物线运动
          + w₉ × 光流不一致惩罚   ← 移动方向应与光流方向一致

位移惩罚示例:
  如果 dist(cand_i, cand_j) > max_speed × Δt:
    edge_cost = +∞  (直接剪枝，不连接)
  否则:
    edge_cost ∝ dist(cand_i, cand_j) / (max_speed × Δt)
```

### 4.6 Viterbi 的核心优势

与逐帧贪心匹配的对比：

```
逐帧贪心:
  帧1: 选最高分 → 候选A (0.95)                ← 可能是对的
  帧2: 选最高分 → 候选F (0.88)                ← 这个错了！
  帧3: 选最高分 → 候选G (0.92)                ← 被迫继续错
  结果: A → F → G   (局部最优 ≠ 全局最优)

Viterbi (考虑全局):
  评估所有路径:
    A→D→F  cost = 0.3 + 0.2 + 0.4 = 0.9      ← 全局最优!
    A→E→F  cost = 0.3 + 0.5 + 0.3 = 1.1
    A→F→G  cost = 0.3 + 2.0 + 0.2 = 2.5      ← 贪心选了这个
    B→D→F  cost = 0.8 + 0.3 + 0.4 = 1.5
    ...
  输出: A → D → F  (最优路径)
```

关键洞察：Viterbi 能够"向前看"——它不只看前一帧的最佳匹配，而是综合整个序列的上下文信息来判断。如果某一帧的高分候选在全局路径的代价很高（例如帧间运动不合理），Viterbi 会选择一条总分更优的路径。

### 4.7 优缺点

| 优点 | 缺点 |
|------|------|
| 全局最优 —— 不只看上一帧 | 需要缓存一段视频或整个视频 |
| 减少"真→假→真"的短时跳变 | 候选数量太多时计算开销大 |
| 可以综合检测、运动和可见性信息 | 代价函数权重需要认真设计 |
| 离线足球追踪非常合适 | 全局最优依赖候选集合中存在真球 |
| 可以加入物理约束和运动先验 | 长时间视频需要滑动窗口加速 |

### 4.8 与 KF/IMM-KF 的配合使用

这三个算法在追踪系统中是分层协作的，而不是互斥的：

```
在线部分:
  IMM-KF → 逐帧运动预测 + 数据关联

准离线部分 (滑动窗口):
  Viterbi → 30秒窗口内的轨迹全局优化
  
后处理:
  KF 平滑 (RTS Smoother) → 轨迹后处理平滑
```

## 5. 工程实现难点

### 5.1 KF 参数调优

| 难点 | 说明 |
|------|------|
| Q 矩阵设定 | 场景高度依赖，镜头运动大 → Q 需增大 |
| R 矩阵设定 | 需要反映检测器在实际场景中的精度水平 |
| 自适应 Q/R | 不同镜头尺度下 Q 和 R 需要自适应调整 |
| 初始 P 矩阵 | 初始化不当 → 前几帧状态发散 |

KF 参数不当的典型症状：
- Q 太小：KF 过于相信预测，对检测结果反应迟钝，开球后跟踪严重滞后
- Q 太大：KF 过于相信检测，轨迹不平滑，检测抖动直接反映在输出上
- R 太小：KF 过于相信检测，噪声干扰大
- R 太大：KF 对检测反应太慢，响应滞后

### 5.2 状态定义选择

| 选择 | 好处 | 坏处 |
|------|------|------|
| 4 维 (x,y,vx,vy) | 简单，参数少 | 无法处理加速度 |
| 6 维 (+w,h) | 框尺寸也平滑 | 尺寸估计可能不稳定 |
| 8 维 (+ax,ay) | 处理加减速 | 参数多，调参复杂 |
| 归一化坐标 | 对镜头运动更鲁棒 | 物理意义模糊，参数难调 |

### 5.3 IMM-KF 工程细节
- 模型数量和类型需要人工确定——太少覆盖不全，太多冗余计算
- 模型转换矩阵 M 需要经验设定（对角线大 → 模型切换慢，对角线小 → 切换快但不稳定）
- 多个 Q 和 R 的设定使超参数搜索空间成倍增长
- 模型概率初始值不当时需要几帧才能稳定

### 5.4 Viterbi 规模化
- T 帧 × N 候选/帧 → 图节点数 = T×N，边数 = T×N²
- 全连接边 → T×N² 次转移代价计算（N=20, T=1000 → 40万次计算）
- 需要剪枝策略控制计算量：
  - 只保留 Top-K 候选/帧
  - 只连接空间近邻的候选（距离超过 max_speed×Δt 的不连接）
  - 分段 Viterbi（每个镜头段独立优化）

### 5.5 门控策略
- 门控阈值太松 → 容易关联假目标（候选太多）
- 门控阈值太紧 → 容易丢失真目标（漏检）
- 静态门控不适用于镜头运动场景
- 需要基于图像运动补偿的动态门控

### 5.6 镜头切换挑战
- 镜头切换后：KF 预测位置 vs 真实位置 → 可能相距甚远
- 需要精确的镜头切换检测机制来触发 KF 状态重置
- 切换帧附近 Viterbi 不连接跨镜头的候选边
- 切换检测的漏报误报 → 直接影响轨迹质量

### 5.7 代价函数调优
- Viterbi 的多个权重 (w₁...w₉) 需要调优
- 代价量纲不一致：置信度 [0,1] vs 位移 [0,∞] → 需要归一化
- 不同场景下最优权重可能不同（慢速传球 vs 高速长传）
- 需要大量实验验证代价函数设计的合理性
