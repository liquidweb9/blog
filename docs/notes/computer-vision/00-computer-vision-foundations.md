# 计算机视觉基础

---

## 1. CV任务分类与关系

计算机视觉任务可以按输出粒度分为图像级、区域级、像素级和视频级四个层次。

```
CV 任务谱系:

图像级理解
  ├── 图像分类 Classification       → "图里有什么？"      → 整图标签
  ├── 图像检索 Image Retrieval      → "找相似的图"        → 排序列表
  └── 图像描述 Image Captioning     → "描述这个图"        → 文本

区域级理解
  ├── 目标检测 Object Detection     → "物体在哪，是什么？"  → 框+类别
  └── 关键点检测 Keypoint Detection → "关节在哪？"        → 关键点坐标

像素级理解
  ├── 语义分割 Semantic Segmentation   → "每个像素属于哪类？"  → 像素类别图
  └── 实例分割 Instance Segmentation   → "每个个体在哪？"     → 像素级掩码

视频级理解
  ├── 目标追踪 Object Tracking         → "物体怎么移动的？"  → 时空轨迹
  ├── 动作识别 Action Recognition      → "视频里在做什么？"  → 动作类别
  ├── 时序动作定位 Temporal Localization → "什么时候做了什么？" → 时间段+类别
  ├── 事件定位 Action Spotting         → "事件发生在哪一帧？" → 时间戳+类别
  ├── 视频问答 Video QA                → "关于视频提问"     → 自然语言答案
  ├── 视频检索 Video Retrieval         → "找到包含X的视频"  → 视频片段
  └── 视频摘要 Video Summarization     → "视频讲了什么？"   → 文本/关键帧
```

### 1.1 任务间依赖关系

```
底层任务 ─────────────────────────→ 上层任务

目标检测
    │
    ├──→ 目标追踪 (需要检测框作为输入)
    │         │
    │         ├──→ 动作识别 (需要追踪轨迹)
    │         └──→ 事件检测 (需要时空轨迹)
    │
    └──→ 实例分割 (检测框+掩码细化)
              │
              └──→ 场景理解

实际项目中通常构建分层流水线:
  底层视觉模型 → 检测/追踪 → 中层分析 → 事件/语义 → 上层检索/问答
```

关键认知：这些任务不是孤立的，而是层层递进的关系。目标检测是追踪的基础，追踪又是动作分析和事件检测的基础。设计系统时不应只考虑某一层的性能——底层模型的一个小错误会在流水线中被逐级放大。

| 任务 | 输入 | 输出 | 典型模型 | 在足球分析中的角色 |
|------|------|------|---------|-----------------|
| 图像分类 | 图像 | 类别标签 | ResNet, ViT | 场景识别（特写/远景/回放） |
| 目标检测 | 图像 | 框+类别 | YOLO, RT-DETR | 检测球员、球、裁判 |
| 语义分割 | 图像 | 像素级类别 | DeepLab, SegFormer | 场地区域分割 |
| 目标追踪 | 视频+检测框 | 时空轨迹 | SORT, ByteTrack | 追踪球和球员 |
| 动作识别 | 视频片段 | 动作类别 | SlowFast, VideoMAE | 识别传球/射门 |
| 事件定位 | 长视频 | 时间戳+事件 | T-DEED | 检测进球/犯规时刻 |
| 视频检索 | 视频+文本查询 | 相关片段 | CLIP, VSS | 搜索比赛中的特定片段 |

## 2. 图像与视频的数学表示

### 2.1 图像的张量表示

图像在计算机中表示为多维张量：

```
RGB 彩色图像:
  形状: C × H × W = 3 × H × W
  
  通道0 (R: 红色):
    ┌─────────────────┐
    │ 125 200 180 ... │
    │ 130 210 175 ... │
    │ ...             │
    └─────────────────┘
  
  通道1 (G: 绿色):
    ┌─────────────────┐
    │ 80  150 130 ... │
    │ 85  160 128 ... │
    │ ...             │
    └─────────────────┘
  
  通道2 (B: 蓝色):
    ┌─────────────────┐
    │ 50  100 90  ... │
    │ 55  110 85  ... │
    │ ...             │
    └─────────────────┘

灰度图像: 1 × H × W (单通道)
每个像素取值: 0-255 (8位) 或 0-65535 (16位)
```

| 分辨率 | 像素数 | 典型应用 |
|--------|--------|---------|
| 1080p (1920×1080) | ~2M | 广播视频、高清部署 |
| 720p (1280×720) | ~1M | 中等质量视频 |
| 640×640 | ~0.4M | YOLO 标准输入 |
| 640×480 | ~0.3M | 低分辨率设备 |

### 2.2 视频的张量表示

视频在图像的基础上增加了时间维度：

```
视频张量: T × C × H × W

  T = 帧数
  C = 通道数 (通常 3, RGB)
  H = 高度
  W = 宽度

示例: 10秒 25fps 720p 视频
  张量形状: 250 × 3 × 720 × 1280
  原始大小: 250 × 3 × 720 × 1280 × 1 byte ≈ 660 MB (未压缩)
```

**帧率 (FPS)** 决定时间采样密度：

| 帧率 | 典型场景 | 对模型的影响 |
|------|---------|------------|
| 25 FPS | 欧洲广播标准 | 相邻帧运动位移适中 |
| 30 FPS | 北美/亚洲广播标准 | 比 25fps 多 20% 的数据量 |
| 50 FPS | 体育赛事高速摄像机 | 运动更连续但数据翻倍 |
| 60-120 FPS | 慢动作回放 | 极端平滑，但数据量巨大 |

在实际工程中，经常根据任务需求对视频进行降采样：
- 目标检测/追踪：保持原始帧率（需要连续运动信息）
- 动作识别：降采样到 8-16 FPS（动作在较低帧率下仍可识别）
- 事件定位：降至 2 FPS（事件是稀疏的，不需要每帧判断）

### 2.3 色彩空间选择

| 色彩空间 | 通道 | 特点 | 工程注意事项 |
|---------|------|------|------------|
| RGB | Red, Green, Blue | 显示器原生，通道相关性高 | OpenCV 默认 BGR（不是 RGB！） |
| HSV | Hue, Saturation, Value | 色调/饱和度/明度分离，对光照变化鲁棒 | 色相在 0-360° 循环 |
| YUV | Luma, Chroma | 亮度/色度分离，色度可降采样 | 广泛用于视频编码 |
| Lab | L (亮度), a (绿-红), b (蓝-黄) | 感知均匀，适合颜色差异计算 | 计算开销比 RGB 大 |

常见工程陷阱：OpenCV 的 `cv2.imread()` 默认读入为 BGR 格式，而 matplotlib 和大多数深度学习框架期望 RGB。忘记做 `cv2.cvtColor(img, cv2.COLOR_BGR2RGB)` 会导致颜色通道错乱。

### 2.4 关键视频概念

```
Clip (视频片段):
  ┌─────────────────────────────────────┐
  │ 完整视频 (T_total 帧)                │
  │  ├── Clip 1 (帧 0-15)               │
  │  ├── Clip 2 (帧 8-23)  ← 可与上一Clip重叠
  │  ├── Clip 3 (帧 16-31)              │
  │  └── ...                            │
  └─────────────────────────────────────┘

特征图 (Feature Map):
  输入图像:  H × W × 3
       ↓ Backbone
  浅层特征: (H/4) × (W/4) × 64     ← 高分辨率，边缘/纹理信息
  中层特征: (H/8) × (W/8) × 128    ← 中等分辨率，部件信息
  深层特征: (H/16) × (W/16) × 256  ← 低分辨率，语义信息
  最深层:   (H/32) × (W/32) × 512  ← 极低分辨率，全局语义

时间窗口 (Temporal Window):
  过去的上下文 ← [t-k, ..., t-1, t, t+1, ..., t+k] → 未来的上下文
                  ↑────── 以帧t为中心的窗口 ──────↑
```

## 3. 深度学习三大组件：CNN、Transformer与RNN

### 3.1 模型能力对比

| 模型 | 提取什么 | 感受野 | 并行化 | 长程依赖 | 计算复杂度 |
|------|---------|--------|--------|---------|-----------|
| CNN | 局部空间特征 | 受限（需堆叠层扩大） | 高 | 弱 | O(k²·H·W) |
| Vision Transformer | 全局空间关系 | 全局（单层即覆盖） | 高 | 强 | O((HW/P²)²) |
| 3D CNN | 时空局部特征 | 受限（空域+时域） | 高 | 弱 | O(k³·T·H·W) |
| RNN/LSTM | 时间顺序依赖 | 理论上无限（实践中几十步） | 低（串行） | 中 | O(T·d²) |
| Transformer Encoder | 长距离时间依赖 | 全局（整序列） | 高 | 强 | O(T²) |
| Temporal Conv (TCN) | 多尺度时间特征 | 受膨胀率控制 | 高 | 中 | O(k·T) |

### 3.2 CNN：空间特征提取的主力

卷积神经网络的核心操作是卷积——用可学习的滤波器在图像上滑动，提取局部空间特征。

```
CNN 的层次化特征:

输入图像
  ↓ Conv1: 边缘检测
边缘图 (竖边、横边、角点)
  ↓ Conv2: 纹理组合
纹理特征 (条纹、斑点、网格)
  ↓ Conv3: 部件组合
部件特征 (眼睛、轮子、把手)
  ↓ Conv4: 物体组合
语义特征 (人脸、汽车、杯子)
  ↓ Conv5: 全局场景
高层语义 (室内/室外、城市场景)
```

**关键设计演进**：

| 架构 | 年份 | 核心创新 | 解决的问题 |
|------|------|---------|-----------|
| LeNet-5 | 1998 | 最早的 CNN（手写数字） | — |
| AlexNet | 2012 | ReLU + Dropout + GPU 训练 | 深层 CNN 训练困难 |
| VGG | 2014 | 小卷积核堆叠（3×3） | 参数量过大 |
| ResNet | 2015 | 残差连接（skip connection） | 深层网络梯度消失 |
| MobileNet | 2017 | 深度可分离卷积 | 模型太大无法部署 |
| CSPNet | 2019 | 跨阶段局部连接 | 计算冗余 + 梯度信息重复 |
| ConvNeXt | 2022 | CNN "现代化"（仿 ViT 设计） | CNN 被 ViT 超越 |

残差连接（ResNet 的核心）解决的问题：
```
普通网络:                    残差网络:
x → Conv → ReLU → Conv      x → Conv → ReLU → Conv
    ↓ 梯度只能走这条长路       ↘         +        ↗
    容易消失                     ↘ 梯度直接短路 ↗
                                永远不会消失
```

### 3.3 Vision Transformer：全局关系建模

ViT 的工作流程：

```
输入图像 (H × W × 3)
     ↓
切分为 Patch (如 16×16 像素)
     ↓
┌──────────────┐  ┌──────────────┐       ┌──────────────┐
│ Patch 1      │  │ Patch 2      │  ...  │ Patch N      │
│ 16×16×3 → d  │  │ 16×16×3 → d  │       │ 16×16×3 → d  │
└──────────────┘  └──────────────┘       └──────────────┘
     ↓                  ↓                      ↓
[CLS] token + Positional Encoding + Patch Embeddings
     ↓
┌─────────────────────────────────────────────────┐
│            Transformer Encoder × L               │
│  ┌── Multi-Head Self-Attention ──┐              │
│  │  每个 Patch 与所有 Patch 计算注意力  │         │
│  └──────────────┬───────────────┘              │
│                 ↓                               │
│  ┌── Feed-Forward Network (MLP) ──┐             │
│  └──────────────┬───────────────┘              │
└─────────────────┬───────────────────────────────┘
                  ↓
         [CLS] token → 分类输出
```

ViT 的优势和代价：
- 优势：自注意力全局感受野，直接建模任意两个 Patch 之间的关系
- 代价：O(N²) 的计算复杂度（N = Patch 数量），高分辨率图像代价极高

**Swin Transformer 的改进**：将自注意力限制在局部窗口内，窗口之间通过移位操作交互，实现线性复杂度：
```
窗口注意力:
┌──┬──┬──┬──┐
│A1│A2│A3│A4│   窗口 A: Patch 1-4 内部注意力
│B1│B2│B3│B4│   窗口 B: Patch 5-8 内部注意力
│C1│C2│C3│C4│   移位后: 跨窗口交互
│D1│D2│D3│D4│
└──┴──┴──┴──┘
```

**DINO 系列（自监督 ViT）**：DINOv2 展示了自监督训练可以在 ViT 中产生高质量语义特征——其特征甚至包含显式的物体边界和语义对应，而不需要任何人工标注。1024 维的 DINOv2 特征可以直接用于图像匹配和检索，这是 CNN 难以做到的。

### 3.4 Transformer 的核心机制

**Scaled Dot-Product Attention**：

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

```
直观理解:
  Q (Query):  "我要找什么？"  — 当前位置想要关注什么信息
  K (Key):    "我是什么？"    — 其他位置能提供什么信息
  V (Value):  "我的内容"      — 其他位置的实际特征内容
  
  Q·K^T → 计算"我要找的"和"你能提供的"的匹配度
  softmax → 归一化为注意力权重 (总和=1)
  × V    → 按权重提取其他位置的内容
  /√d_k  → 防止点积过大导致 softmax 梯度饱和
```

**多头注意力 (Multi-Head Attention)**：

将 Q/K/V 分成 h 个子空间，并行计算 h 次注意力，拼接结果：

```
Q → [Q₁, Q₂, ..., Q_h]      (每个头维度 = d/h)
K → [K₁, K₂, ..., K_h]
V → [V₁, V₂, ..., V_h]

每个头:
  headᵢ = Attention(Qᵢ, Kᵢ, Vᵢ)    ← 关注不同的关系模式

输出 = Concat(head₁, ..., head_h) × Wₒ
```

多头让模型在不同子空间中关注不同类型的关系——有的头关注局部纹理匹配，有的关注全局结构关系，有的关注物体之间的相对位置。

**位置编码**：自注意力本身是置换等变的（打乱输入顺序，输出也相应变化但值不变），因此需要位置编码注入位置信息：

| 编码方式 | 说明 | 优点 | 缺点 |
|---------|------|------|------|
| 绝对位置编码 (Sinusoidal) | `PE(pos,2i) = sin(pos/10000^(2i/d))` | 可外推到训练未见的长度 | 表达能力有限 |
| 可学习位置编码 | 直接学习位置嵌入 | 灵活，适合固定长度 | 无法外推 |
| RoPE (旋转位置编码) | 在 Q·K 计算中注入相对位置 | 天然捕获相对位置，外推性好 | 实现稍复杂 |

### 3.5 RNN/LSTM/GRU：时序建模的先驱

```
RNN 展开结构:

  y₁        y₂        y₃        y₄
  ↑         ↑         ↑         ↑
  h₀ → [h₁] → [h₂] → [h₃] → [h₄] → ...
  ↑     ↑     ↑     ↑
  x₁    x₂    x₃    x₄

  hₜ = f(W·xₜ + U·hₜ₋₁ + b)
  
  问题: 梯度反向传播时，经过的每一步都对梯度做一次乘
        → 梯度过小(消失)或过大(爆炸)
```

LSTM 引入门控机制解决梯度消失：

```
LSTM 内部结构 (一个时间步):

       遗忘门: "丢掉哪些旧记忆？"
  hₜ₋₁ ──→ σ(W_f·[hₜ₋₁, xₜ]) ──→ 作用于 Cₜ₋₁

       输入门: "记住哪些新信息？"
  hₜ₋₁ ──→ σ(W_i·[hₜ₋₁, xₜ]) ──→ 作用于新候选记忆

       输出门: "输出多少记忆？"
  hₜ₋₁ ──→ σ(W_o·[hₜ₋₁, xₜ]) ──→ 作用于当前状态 hₜ
```

尽管 LSTM 曾是时序建模的主力，但它存在本质缺陷（串行计算无法并行，长序列效率低）。在视觉时序建模中，LSTM 已被 Transformer 和时序卷积（Temporal Convolution）取代。

## 4. 特征层次与Backbone-Neck-Head范式

### 4.1 特征层次与多尺度

```
CNN 多尺度特征金字塔:

输入图像 640×640×3
     ↓
Stage 1: 320×320×64      ← 高分辨率，低语义
     ↓                       (P1 通常不用)
Stage 2: 160×160×128     ← P2: 可用但计算量最大
     ↓
Stage 3: 80×80×256       ← P3: 小目标检测
     ↓
Stage 4: 40×40×512       ← P4: 中目标检测
     ↓
Stage 5: 20×20×1024      ← P5: 大目标检测
```

浅层特征（P2-P3）分辨率高、语义弱，适合定位边缘和细节。深层特征（P4-P5）语义强、分辨率低，适合识别物体类别。目标检测恰好需要同时利用两者——检测小目标需要浅层的高分辨率细节，检测大目标需要深层的语义信息。

**FPN（Feature Pyramid Network）** 解决了这个矛盾：

```
FPN 结构:

        P5 (20×20) ──→ M5 (20×20) ──→ 输出 P5_out
                         ↓ 上采样
        P4 (40×40) ──→ M4 (40×40) ──→ 输出 P4_out
                         ↓ 上采样
        P3 (80×80) ──→ M3 (80×80) ──→ 输出 P3_out

自顶向下: 深层语义传递到浅层
横向连接: 每层融合自己的原始特征
结果: 每一层都同时拥有语义 + 空间分辨率
```

| Neck 结构 | 信息流向 | 特点 | 使用模型 |
|-----------|---------|------|---------|
| FPN | 自顶向下 | 基础多尺度融合 | Faster R-CNN, RetinaNet |
| PAN | FPN + 自底向上 | 定位信息也上传到深层 | YOLOv5/v8/v11 |
| BiFPN | 可学习加权融合 | 网络自主决定各层重要性 | EfficientDet |
| Hybrid Encoder | Intra-scale + Cross-scale | CNN + Transformer 混合 | RT-DETR |

### 4.2 Backbone-Neck-Head 范式

现代检测和分割模型普遍遵循三层结构：

```
┌────────────────────────────────────────┐
│              Backbone (特征提取器)       │
│                                         │
│  ResNet / CSPDarknet / Swin / DINOv3   │
│                                         │
│  作用: 从原始 RGB 图像中提取通用视觉特征 │
│  输出: 多尺度特征图 (P3, P4, P5, ...)   │
│  特点: 可替换，不同 Backbone 即插即用   │
└────────────────┬───────────────────────┘
                 ↓
┌────────────────────────────────────────┐
│              Neck (特征融合层)           │
│                                         │
│  FPN / PAN / BiFPN / Hybrid Encoder    │
│                                         │
│  作用: 融合不同尺度的 Backbone 特征      │
│  输出: 增强的多尺度特征表示              │
│  特点: 缓解浅层定位 vs 深层语义的矛盾    │
└────────────────┬───────────────────────┘
                 ↓
┌────────────────────────────────────────┐
│              Head (任务特定预测头)       │
│                                         │
│  分类头 / 回归头 / Objectness / ...     │
│                                         │
│  作用: 将特征映射为具体任务输出          │
│  输出: 类别概率 + 边界框 + 分割掩码等   │
│  特点: 不同任务可复用同一 Backbone+Neck  │
└────────────────────────────────────────┘
```

这种分离设计的核心优势：各组件可独立替换和优化。你可以用 ResNet、Swin 或 DINOv2 作为 Backbone 而不改变 Head 结构，也可以为不同任务替换 Head 而复用相同的 Backbone+Neck 特征。

## 5. 学习范式

### 5.1 监督学习

监督学习是精度最高的方案，但需要大量人工标注。

```
监督学习流程:

  训练图像 + 人工标注(类别/框/掩码)
         ↓
    前向传播 → 预测
         ↓
   Loss = 预测与标注的差异
         ↓
    反向传播 → 更新参数
         ↓
      重复至收敛
```

| 数据集 | 规模 | 任务 | 标注类型 |
|--------|------|------|---------|
| ImageNet | 128万图/1000类 | 图像分类 | 类别标签 |
| COCO | 20万图/80类 | 检测+分割 | 边界框+掩码 |
| Pascal VOC | 1.5万图/20类 | 检测+分割 | 边界框+掩码 |
| SoccerNet | 550场比赛 | 多种足球任务 | 事件时间戳+追踪框 |

### 5.2 自监督学习

自监督学习不依赖人工标注，通过"预设计任务"从数据本身学习视觉特征。

```
主流自监督方法对比:

┌─ 对比学习 (Contrastive) ───────────────────┐
│  SimCLR, MoCo                               │
│                                             │
│  同一张图两个增强 → 特征距离近               │
│  不同图的增强     → 特征距离远               │
│                                             │
│  Loss: InfoNCE (Info Noise-Contrastive Estimation) │
│  缺点: 需要大量负样本（或巨大的 batch size）  │
└─────────────────────────────────────────────┘

┌─ 掩码图像建模 (MIM) ───────────────────────┐
│  MAE, SimMIM, BEiT                          │
│                                             │
│  随机遮盖图像的 Patch                        │
│  模型预测被遮盖的内容                        │
│                                             │
│  优点: 不需要负样本                          │
│  缺点: 偏向像素级重建 ≠ 高层语义            │
└─────────────────────────────────────────────┘

┌─ 知识蒸馏 (Distillation) ────────────────────┐
│  DINO, DINOv2                                │
│                                               │
│  Student 网络预测 ← 增强版本 a                 │
│  Teacher 网络预测 ← 增强版本 b                 │
│  Student 逼近 Teacher (EMA 更新 Teacher)       │
│                                               │
│  优点: 学到的特征包含丰富的语义和边界信息      │
│  代表: DINOv2 — 1.42亿张图自监督训练         │
└───────────────────────────────────────────────┘
```

**DINOv2 的里程碑意义**：在 1.42 亿张精选图像上自监督训练，学到的特征在分类、检测、分割、深度估计等任务上达到极强表现，甚至不需要微调即可用于稠密匹配和语义对应。它是目前最强大的通用视觉 Backbone 之一。

### 5.3 迁移学习与微调

这是当前 CV 的实际标准做法——几乎没有人从头训练模型。

```
迁移学习三种策略:

① Head-only 微调 (最轻量):
   冻结 Backbone ← 预训练权重 (不变)
   只训练 Head   ← 适配新任务
   适合: 数据极少 (几百张图)，任务差异大

② Full Fine-tuning (全参数微调):
   全部参数都参与训练 ← 预训练权重 (初始化)
   学习率: 通常为预训练 LR 的 1/10 ~ 1/100
   适合: 数据充足 (几千张+)，预期精度最高

③ Parameter-Efficient Fine-tuning (PEFT):
   冻结大部分参数，只训练少量插入的 adapter / LoRA 权重
   LoRA: 在原权重旁增加低秩分解矩阵 (可训练)
   适合: 大模型 (ViT-Huge 等)，显存不足
```

迁移学习的有效性源于视觉特征的可迁移性——预训练模型已经学会了通用视觉概念（边缘、纹理、形状、物体部件），这些知识对绝大多数视觉任务都有用。

## 6. 损失函数与优化

### 6.1 常见损失函数

| 损失函数 | 公式 | 适用任务 | 特点 |
|---------|------|---------|------|
| Cross Entropy (CE) | $-\sum y_i \log(p_i)$ | 分类 | 标准分类损失 |
| Focal Loss | $-\alpha(1-p_t)^\gamma \log(p_t)$ | 检测(分类) | 降低 easy 样本权重，聚焦 hard 样本 |
| Varifocal Loss (VFL) | 类似 Focal + IoU 加权 | 检测(分类) | 分类分数同时也编码定位质量 |
| L1 Loss | $\| \hat{y} - y \|$ | 回归 | 简单，对大误差敏感 |
| Smooth L1 | 小误差 L2 + 大误差 L1 | 回归 | 对大误差不敏感，更稳定 |
| IoU Loss | $-\ln(\text{IoU})$ | 框回归 | 直接优化重叠面积（尺度不变） |
| GIoU Loss | IoU + 最小闭包惩罚 | 框回归 | IoU=0 时仍提供梯度 |
| CIoU Loss | IoU + 距离 + 长宽比 | 框回归 | 收敛最快，YOLO 标准选择 |

### 6.2 优化器对比

| 优化器 | 特点 | 使用场景 |
|--------|------|---------|
| SGD + Momentum | 需要精细调 LR，泛化性好 | 传统方法，精细训练 |
| Adam | 自适应 LR，收敛快 | 新模型快速实验 |
| AdamW | 正确实现权重衰减的 Adam | 当前 CV 训练主流 |
| AdamW + Cosine LR | 余弦退火 + 自适应 LR | 现代 SOTA 训练标准 |

## 7. 模型评估指标

| 任务 | 核心指标 | 含义 |
|------|---------|------|
| 分类 | Accuracy, F1 | 正确率，准确率与召回率的调和平均 |
| 检测 | mAP@0.5:0.95 | 多个 IoU 阈值的平均精度（COCO 标准） |
| 分割 | mIoU | 各类别平均交并比 |
| 追踪 | MOTA, MOTP, ID Switch | 追踪准确度/精度/ID 切换次数 |
| 事件定位 | Average-mAP | 多个时间容忍度下的平均 mAP |

## 8. 模型部署与推理加速

### 8.1 模型压缩策略

| 方法 | 压缩率 | 精度损失 | 原理 |
|------|--------|---------|------|
| 剪枝 (Pruning) | 30-50% | 小 | 移除贡献小的参数/通道 |
| INT8 量化 | 4× 加速 | 中（小目标明显） | FP32 → INT8 |
| FP16 | 2× 加速 | 极小 | FP32 → FP16 |
| 知识蒸馏 | 模型缩小 3-10× | 小 | 大模型教小模型 |

### 8.2 推理引擎选择

| 引擎 | 平台 | 加速倍数 | 适用场景 |
|------|------|---------|---------|
| ONNX Runtime | 跨平台 | 1-2× | 通用部署 |
| TensorRT | NVIDIA GPU | 2-5× | 服务器 GPU 推理 |
| OpenVINO | Intel CPU/GPU | 2-4× | Intel 设备 |
| TFLite / NCNN | 移动端 | 2-3× | 边缘设备 |
