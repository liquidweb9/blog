# 足球完整追踪流水线

---

## 1. 系统解决什么问题

构建一条从原始视频到精确足球轨迹的完整处理流水线，处理广播足球视频中目标极小、高速运动、频繁遮挡、镜头切换等挑战，输出稳定可靠的足球时空轨迹。

## 2. 为什么需要完整流水线

- 单一检测器无法解决遮挡和跳变
- 单一运动模型（KF）无法适应复杂运动模式
- 单帧决策（逐帧匹配）容易积累错误
- 需要多模块协同：检测提供候选、运动模型提供预测、时序模型提供验证、全局优化提供纠错

## 3. 系统输入与输出

- 输入：广播足球比赛视频（任意时长，25-50 FPS）
- 输出：
  - 足球轨迹（每帧位置 + 可见性标志）
  - 球员轨迹（可选）
  - 镜头切换列表（可选）

## 4. 整体架构

```
                   视频帧序列
                       │
            ┌──────────┼──────────┐
            ↓          ↓          ↓
       RT-DETR    TrackNet/    CoTracker
       单帧检测    TOTNet      点追踪
            │      时序热图       │
            │          │          │
            └──────────┼──────────┘
                       ↓
                 候选融合
            (多源候选合并+去重)
                       ↓
              ROI Tube Scorer
            (时序候选评分模块)
                       ↓
              Visibility Head
              (可见性置信度)
                       ↓
              IMM-KF运动预测
            (多模型运动估计)
                       ↓
           ┌──────────┼──────────┐
           ↓          ↓          ↓
     镜头切换检测    候选图构建    门控过滤
                       │
                       ↓
               Viterbi全局优化
              (最优轨迹路径)
                       │
                       ↓
              轨迹平滑与补全
              (填补短期间隙)
                       │
                       ↓
               最终足球轨迹
```

## 5. 核心模块详解

### 5.1 检测器模块 (RT-DETR)

- 配置：RT-DETRv4-L，输入1280x1280
- 输出：每帧Top-20个足球候选框（置信度降序）
- 置信度通常偏低：0.2-0.8
- 推理速度：~90 FPS on T4

关键参数：
- 置信度阈值：0.05（保留大量候选供后续筛选）
- NMS阈值：0.7
- 最大检测数：20

### 5.2 时序热图模块 (TrackNet/TOTNet)

- 输入：连续5-16帧clip
- 输出：球位置热图 + 可见性
- 作用：提供基于时间上下文的检测结果，补充单帧检测的不足
- 推理速度：依赖窗口大小和模型规模

### 5.3 点追踪模块 (CoTracker)

- 作用：在检测框内部采样点，追踪短时间窗口内的精细运动
- 输出：采样点的轨迹和可见性
- 主要用于交叉验证：检测候选点与CoTracker轨迹的一致性

### 5.4 ROI Tube Scorer

输入：候选框序列 + 对应图像区域
输出：每个候选的时序一致性评分

评分维度：
- 外观一致性：候选在不同帧的外观特征相似度
- 运动连续性：候选的运动是否符合物理规律
- 检测置信度：单帧检测器给出的置信度
- 热图一致性：TrackNet/TOTNet热图在该位置的响应

### 5.5 Visibility Head

- 输入：候选框周围ROI区域
- 输出：（0~1）的可见性分数
- 训练：使用带有可见性标注的数据
- 用途：在Viterbi节点代价中加权

### 5.6 IMM-KF

- 维护3-4个并行运动模型：
  - 匀速模型 (CV)：适合滚地、平稳传球
  - 匀加速模型 (CA)：适合踢球加速、减速
  - 高机动模型：适合碰撞、急转向
  - 近似静止模型：适合定位球、死球
- 模型概率自适应切换
- 预测位置用于候选图构建的边代价计算

### 5.7 镜头切换检测

- 方法1：帧间直方图差异
- 方法2：检测框集合的剧烈变化检测
- 方法3：基于场景相似度（CLIP特征）
- 输出：镜头切换帧索引列表
- 用途：Viterbi分段处理，切换点前后不做跨镜头候选连接

### 5.8 候选图构建

```
帧1: [cand_1_1, cand_1_2, ..., cand_1_n1]
帧2: [cand_2_1, cand_2_2, ..., cand_2_n2]
...
帧T: [cand_T_1, cand_T_2, ..., cand_T_nT]

节点 = (帧索引, 候选索引)
边 = (节点_i, 节点_j) 其中 j = i+1

节点代价 = f(检测置信度, 可见性分数, 时序一致性)
边代价 = g(位移, 速度变化, 方向变化, 光流一致性)
```

### 5.9 Viterbi优化

动态规划状态转移：
```
dp[t][j] = max_i { dp[t-1][i] + edge_cost(i, j) } + node_cost(j)
```

输出最优路径 = argmax dp[T]

### 5.10 轨迹平滑与补全

- 平滑：Savitzky-Golay滤波器或卡尔曼平滑
- 补全：短时间遮挡（<1秒）用线性/样条插值
- 长时遮挡：标记为不可见

## 6. 设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 检测器 | RT-DETRv4 | 精度速度平衡好，小目标检测强 |
| 运动模型 | IMM-KF | 适应多种运动模式 |
| 关联方式 | Viterbi全局 | 解决跳变 |
| 候选评分 | Tube Scorer | 时序一致性过滤假球 |
| 可见性 | 独立Head | 显式建模遮挡 |
| 镜头切换 | 检测+重置 | 切换时中断轨迹 |

## 7. 运行流程

### 在线模式（实时）
```
while video_running:
    frame  ← capture()
    dets   ← detector(frame)
    cands  ← filter(dets, threshold=0.1)
    tracks ← iou_match(cands, active_tracks, kf_predictions)
    output current position
```

- 无Viterbi，无Tube Scorer（延迟大）
- 使用IMM-KF + 轻度匹配

### 离线模式（高精度）
```
frames = load_video()
for each frame:
    dets = detector(frame)
    heatmaps = tracknet(clip)
    cands = merge_candidates(dets, heatmaps)

# 批处理阶段
tubes = tube_scorer(cands)
visibilities = visibility_head(tubes)
shot_boundaries = shot_detection(frames)
graph = build_candidate_graph(cands, tubes, visibilities)
trajectory = viterbi(graph, shot_boundaries)
trajectory = smooth_and_fill(trajectory)
```

## 8. 评估结果

| 指标 | 在线模式 | 离线模式 |
|------|---------|---------|
| Center Error | 12-18px | 6-10px |
| Recall | 75-80% | 88-93% |
| ID Switch | 20-30次/半场 | <5次/半场 |
| 速度 | 30-50 FPS | 10-20 FPS |

## 9. 工程实现难点

### 9.1 流水线延迟管理
- 检测器+追踪器+后处理的全流程延迟分配
- 检测器占用60-70%的推理时间
- 并行化：GPU推理 + CPU后处理异步
- 流水线级联时的一帧延迟积累

### 9.2 多模块同步
- 不同模块处理速度不一致需要缓冲
- 检测器90FPS vs Viterbi 10FPS → 需要异步中间存储
- 候选信息的传递格式统一
- 模块依赖关系管理（检测→评分→优化）

### 9.3 显存优化
- TrackNet/TOTNet + RT-DETR同时加载显存可能超限
- 需要分阶段部署或模型共享
- 视频帧缓存的管理策略
- 候选图存储随视频长度线性增长

### 9.4 参数配置管理
- 每个模块都有多个敏感参数
- 参数之间的耦合关系复杂（检测阈值影响候选数量，候选数量影响Viterbi速度）
- 需要自动化参数搜索
- 不同比赛场景可能需要不同参数配置

### 9.5 异常处理
- 空候选帧的处理策略
- 长时间遮挡后的轨迹重新初始化
- 镜头切换检测的漏报和误报处理
- 单模块异常的容错机制

### 9.6 视频数据结构
- 广播视频的帧率不固定（慢动作回放帧率变化）
- 不同编码格式的帧解码效率差异
- 跳帧采样策略需要与帧率对齐
- 时间戳管理（原始时间戳 vs 帧索引）

## 10. 实验配置

- GPU: NVIDIA T4/RTX 3090/A10
- 检测器输入: 1280x1280
- 候选保留: 每帧Top-20
- Viterbi窗口: 全视频（离线）或30秒滑动窗口（准在线）
- 镜头切换检测: 帧间直方图Chi-Square差异

## 11. 失败案例

- 球完全出画面后重新入场时轨迹重新初始化延迟
- 多个白色运动目标（球+白鞋+广告）同时运动时Viterbi最优路径可能是假球
- 夜间比赛低光照条件下检测器+热图同时失效
- 慢动作回放插入导致帧率突变，时间戳管理混乱

## 12. 可以继续改进的方向

- 端到端训练：将检测+追踪融入统一网络
- 多视角融合：利用多个机位交叉验证球的位置
- 物理模型引导：引入空气动力学和碰撞模型约束
- 在线自适应：流水线在推理过程中根据场景自动调整参数
- 球员-球交互模型：用球员位置推理球可能的位置
