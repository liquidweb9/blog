# 知识蒸馏：小模型如何向大模型学习？

## 一句话结论

**知识蒸馏（Knowledge Distillation）让学生模型学习教师模型的输出分布、内部特征或生成结果，把教师的部分能力迁移到更容易部署的模型中。它迁移的是训练信号，不是直接复制权重；能否兼顾质量与成本，取决于教师、学生容量、数据覆盖和评估方式。**

可以把它理解为：老师不仅告诉学生“正确答案是什么”，还提供“其他答案有多接近”或“怎样组织答案”的示范。学生学完后，通常可以独立推理，不再逐次调用老师。

## 1. 为什么不直接部署教师模型？

假设一个工单分类服务需要把请求分成“退款、物流、账户、其他”。大型模型或多个模型组成的集成可能判断得更准确，但线上还有延迟、显存和成本约束。

一种做法是选择较小的学生模型，让教师在训练阶段提供额外监督：

```text
                     ┌→ 教师模型（通常冻结）→ 概率分布 / 特征 / 答案 ┐
训练输入 ────────────┤                                             ├→ 训练损失
                     └→ 学生模型（可训练） ─→ 学生预测 ───────────────┘
真实标签（如果有） ─────────────────────────────────────────────────┘
                                      ↓
                                只更新学生参数
                                      ↓
线上请求 ────────────────────────→ 学生模型 → 返回结果
```

教师通常更强，但不一定是一个更大的模型：它也可以是模型集成，或者在自蒸馏中来自同一架构的不同阶段。学生也不必采用与教师相同的网络结构。

**蒸馏本身不保证模型变小。** 常见的压缩收益来自选择更小的学生，再用蒸馏尽量弥补质量差距；如果学生架构没有变化，也可能只是提升质量或改变行为。

## 2. 软标签：除了正确答案，还能学到什么？

普通分类训练使用真实标签。例如一张猫的图片，对“猫、狗、汽车”三个类别的硬标签是：

```text
硬标签：[1, 0, 0]
```

它告诉学生“这是猫”，却没有直接表达“猫与狗比猫与汽车更容易混淆”。教师的概率分布可以提供这些相对关系。

假设教师输出的 Logits，也就是 Softmax 之前的原始分数，为 `[4, 2, 0]`：

| 监督信号 | 猫 | 狗 | 汽车 |
| --- | --- | --- | --- |
| 真实硬标签 | 1.000 | 0.000 | 0.000 |
| 教师分布，温度为 1 | 0.867 | 0.117 | 0.016 |
| 教师分布，温度为 2 | 0.665 | 0.245 | 0.090 |

这些非最大类别的概率常被称为 **Dark Knowledge（暗知识）**：它们可能包含教师学到的类别相似性和决策边界信息。学生学习整个分布，比只学习教师选出的类别多获得一层监督。

不过，这仍然是教师的判断，不是真实世界的保证。教师如果把背景纹理当成分类依据，学生也可能学到同样的偏差。

### 2.1 温度为什么能让分布更柔和？

带温度的 Softmax 定义为：

$$
p_i^{(T)} = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}, \qquad T > 0
$$

其中，$z_i$ 是第 $i$ 个类别的 Logit，$T$ 是温度：

- $T=1$：普通 Softmax。
- $T>1$：分布更平缓，让非最大类别的相对概率更容易参与学习。
- $0<T<1$：分布更尖锐，更集中于高分候选。

蒸馏时，教师和学生应使用同一个蒸馏温度来比较分布；太高的温度会使分布接近均匀，未必更有帮助。通常先从少量候选值做验证，而不是把“越高越好”当成规则。

这里的温度作用于**训练中的分布匹配**，与大模型生成答案时使用的采样温度不是同一个配置目的。分类模型部署时通常恢复普通 Softmax，或者直接取 Logits 最大的类别。

## 3. 蒸馏损失：既向老师学，也保留真实标签

对有真实标签的分类任务，一个常见目标是把监督交叉熵与蒸馏损失组合起来：

$$
\mathcal{L}
= (1-\alpha)\,\operatorname{CE}\bigl(y, q^{(1)}\bigr)
+ \alpha T^2\,\operatorname{KL}\bigl(p^{(T)} \Vert q^{(T)}\bigr)
$$

其中：

- $y$ 是真实标签，$p$ 是教师分布，$q$ 是学生分布。
- 第一项让学生学习真实标签，使用温度为 1 的学生分布。
- 第二项让学生匹配教师的软标签，教师与学生都使用温度 $T$。
- $\alpha$ 控制两类监督的权重；本文约定越大越偏向教师。

这里使用的 KL 方向为：

$$
\operatorname{KL}(p \Vert q)
= \sum_i p_i \log \frac{p_i}{q_i}
$$

它衡量学生对教师概率质量的覆盖程度。对于固定教师，最小化这项 KL 与最小化以教师分布为目标的软标签交叉熵，具有相同的学生梯度。

经典做法乘上 $T^2$，用于补偿升温后蒸馏梯度尺度的变化，避免仅改变温度就大幅削弱这一项的影响；这不意味着任意温度下损失和梯度都完全不变。

如果没有人工标签，可以只使用教师监督，但此时也少了一条纠正教师错误的信号。$T$、$\alpha$ 和教师选择都应根据独立验证集确定。

### 3.1 一个 PyTorch 训练示例

下面展示分类任务的训练骨架。假设已准备好经过训练的 `teacher`、待训练的 `student` 和 `train_loader`，两个模型都直接返回形状为 `[batch_size, num_classes]` 的 Logits，类别顺序和输入预处理一致。

```python
import torch
import torch.nn.functional as F


def distillation_loss(student_logits, teacher_logits, labels,
                      temperature=2.0, alpha=0.5):
    hard_loss = F.cross_entropy(student_logits.float(), labels)

    soft_loss = F.kl_div(
        F.log_softmax(student_logits.float() / temperature, dim=-1),
        F.softmax(teacher_logits.detach().float() / temperature, dim=-1),
        reduction="batchmean",
    ) * temperature**2

    return (1 - alpha) * hard_loss + alpha * soft_loss


device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
teacher = teacher.to(device).eval()
teacher.requires_grad_(False)
student = student.to(device).train()
optimizer = torch.optim.AdamW(student.parameters(), lr=1e-4)

for inputs, labels in train_loader:
    inputs = inputs.to(device)
    labels = labels.to(device)
    optimizer.zero_grad(set_to_none=True)

    with torch.no_grad():
        teacher_logits = teacher(inputs)

    student_logits = student(inputs)
    loss = distillation_loss(student_logits, teacher_logits, labels)
    loss.backward()
    optimizer.step()
```

这个例子有几个容易写错的细节：

1. **教师既要 `eval()`，也要关闭梯度。** `eval()` 控制 Dropout、BatchNorm 等层的行为，不会自动停止梯度计算；优化器只更新学生。
2. **`F.kl_div` 的第一个参数是学生的对数概率。** 默认第二个参数是教师概率。上述顺序对应数学上的 $\operatorname{KL}(p_{\text{teacher}} \Vert q_{\text{student}})$，不要把两边写反。
3. **`batchmean` 适用于这里的二维分类分布。** 它先对类别求和，再对样本取平均。大模型的 `[batch, sequence, vocabulary]` 张量还要处理有效 Token 掩码，并按有效 Token 数归一化，不能直接照搬。
4. **示例只展示一个训练轮次。** 实际实验还需要验证集、检查点和训练配置记录；温度、权重和学习率只是起点。

## 4. 大模型蒸馏：学习概率，还是学习生成答案？

“用大模型教小模型”不一定都在执行上述 KL 损失。常见方法可以按监督信号区分：

| 方法 | 学生学习什么 | 需要从教师获得什么 | 主要难点 |
| --- | --- | --- | --- |
| 输出分布蒸馏 | 类别或下一 Token 的概率分布 | Logits 或足够完整的概率信息 | 分布获取、词表对齐、显存和存储 |
| 特征蒸馏 | 隐藏状态、注意力等中间表征 | 教师内部特征 | 层数、维度和语义位置对齐 |
| 序列／生成数据蒸馏 | 教师生成的完整答案或推理示范 | 可用的文本输出 | 数据质量、覆盖度与错误传播 |

### 4.1 能拿到 Logits：按 Token 匹配分布

自回归语言模型每个位置预测下一个 Token。分布蒸馏通常让教师与学生看到**相同的输入和历史前缀**，对相同预测位置的下一 Token 分布计算损失。

除了冻结教师，还需要注意：

- Tokenizer、词表索引和预测位置必须可对齐；不同词表不能直接逐元素算 KL。
- Logits 与标签需要正确做 next-token shift，Padding 和不参与训练的 Prompt 位置要排除。
- 完整词表分布很大，同时运行教师和学生会增加训练显存；离线缓存又会增加存储成本。
- API 返回的 Top-k Logprobs 通常不等于完整词表分布，不能不处理剩余概率质量就当成完整 KL。

### 4.2 只能调用 API：先生成数据，再做 SFT

更容易落地的路径，是让教师生成高质量答案，形成输入—输出样本，再用这些样本对学生做监督微调（SFT）：

```text
训练任务输入 → 教师生成候选答案 → 规则 / 人工 / 独立评测筛选
                                     ↓
                              蒸馏训练数据集
                                     ↓
                         小模型 SFT → 独立评估 → 部署
```

比如让教师根据工单输出固定字段的 JSON，学生学习的是这些示范答案中的 Token 序列。它没有拿到教师对每个候选 Token 的完整概率，因此**不能把这种训练说成逐 Token 的软标签 KL 蒸馏**。

教师生成的解释或推理步骤也可以成为监督信号，但可见的推理文本并不等于教师内部计算过程，文字看起来合理也不保证答案正确。代码任务可结合测试，数学任务可结合答案校验，结构化任务可结合 Schema 与业务规则筛选。

如果用 [Unsloth 与 LoRA/QLoRA](/daily/2026/09/2026-09-23-daily-unsloth-fine-tuning) 训练学生，二者的分工是：**蒸馏决定向谁学、学什么；SFT 和 LoRA/QLoRA 决定如何更新学生参数。**

## 5. 蒸馏、量化和剪枝有什么区别？

它们都可能用于降低部署成本，但改变模型的方式不同：

| 技术 | 主要改变什么 | 与蒸馏的关系 |
| --- | --- | --- |
| 知识蒸馏 | 学生的训练目标和监督信号 | 可以训练一个更小、架构不同的学生 |
| 量化 | 权重或激活的数值精度 | 可以进一步量化蒸馏后的学生 |
| 剪枝 | 参数、通道、层等结构或连接 | 可以在剪枝后用蒸馏恢复部分质量 |
| LoRA | 可训练参数的组织方式 | 可以用于学生微调，本身不减少基础模型参数量 |

例如，“选择小模型 → 蒸馏训练 → 部署量化”是一条可以组合的路径。最终速度仍取决于硬件、算子支持、上下文和批处理；参数更少或精度更低，不自动保证真实服务中的延迟按比例下降。

## 实践建议

1. **先定义任务和部署预算。** 明确要改善的是分类准确率、摘要质量还是工具调用成功率，同时记录目标硬件、上下文长度、P95 延迟和显存上限。
2. **至少保留三个质量基线。** 对比教师、同架构同数据预算下不使用教师监督的学生、蒸馏后的学生；生成数据蒸馏则要明确原始样本与教师样本的差别，避免把增加数据量的收益全部归因于蒸馏方法。
3. **先切分数据，再生成教师监督。** 按文档、用户或问题族分组切分，训练只使用训练部分；验证集用于选配置，独立测试集用于最终评估，防止近似副本泄漏。
4. **覆盖教师和学生的失败场景。** 不只收集容易回答的样本，也加入长输入、歧义、少数类别和格式边界；教师错误应通过真实标签或独立校验处理，而不是无条件复制。
5. **同时测质量与真实部署成本。** 在同一任务集、相同质量要求下比较准确率或任务通过率、P50/P95 延迟、吞吐与峰值显存。生成任务还要记录输入／输出 Token 长度，避免把“答案变短”误认为计算能力提升。
6. **计算一次性成本。** 教师推理、数据筛选和学生训练都要花钱。可用“额外蒸馏成本 ÷ 每次请求节省的成本”粗估回本请求量，再判断是否值得投入。

蒸馏损失下降，只说明学生更接近训练中的教师信号；不代表真实任务一定更准确，也不保证超出训练分布后仍能保持教师的能力。容量太小、教师不适配或数据覆盖不足时，增加训练步数未必能解决问题。

最终可以记住这条主线：**选择合适的教师，用可验证的信号训练合适的学生，再用独立任务评估判断能力是否真正迁移。** 知识蒸馏的价值，是把训练阶段较昂贵的指导转化为推理阶段可持续使用的模型能力。
